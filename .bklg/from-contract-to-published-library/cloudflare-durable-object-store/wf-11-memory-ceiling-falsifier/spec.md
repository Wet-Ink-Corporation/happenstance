## One-line PR slice

Measure this isolate's real memory ceiling from inside the `workerd` run, drive payloads sized against it through the adapter's actual non-streaming encode path — `happenstance-core`'s `serde`-feature payload encoder, the one a peer would use — with a binary-format negative control on the same bytes, and record whether WF-11's falsifier bites; gathering evidence only, changing no wire format.

## Executive summary

WF-11 has carried a `[PROVISIONAL]` marker since phase 5 because its falsifier needs two things in one place — a memory ceiling that is real, and a payload large enough to hit it — and until `every-rule-under-workerd` (HS-S0054) merged, this workspace had neither. That story put an executed wasm32 conformance run inside one `cargo xtask ci`. This PR uses it: a second, small test target in the same crate, mounted the same way, that measures the isolate's ceiling and then encodes against it.

The delta is one instrument and one recorded number set. It adds no conformance rule (WF-11 is a *wire* clause; nothing in the event-store suite can see how much memory an encode took), no public API, no `[dependencies]` entry, no clause edit and no `.kb/` write. What it lands is the first measurement of `payload::serialize`'s whole-payload materialisation taken on a machine where materialisation can actually fail, plus the two controls that stop the measurement being vacuous: a binary-format encode of the *same* bytes, which must come out at a visibly lower cost or the encoder was never exercised, and a registry row that makes an emptied or skipped probe fail the gate rather than pass on `running 0 tests`.

The output is a verdict, in one of exactly three admissible shapes — *it fires at size S*, *it does not fire, with H bytes of measured headroom at the largest size this runtime can be made to attempt*, or *the condition is not constructible here, and this is precisely what would construct it*. `adr-0023-and-atom-resolutions` (HS-S0058) consumes that verdict and moves `.kb/open-questions/human-readable-payload-encoding-on-a-constrained-peer.md` to resolved; `replication-identity-and-ingest` (HS-P0017) decides what, if anything, changes about the wire format. Neither is this PR.

## Context pack

**Decision 1 — the subject is `happenstance-core`'s payload encoder, and the discover ledger's guess about where it lives is corrected here by reading it.** `discover.md`'s signal table says *"the encoder lives in the sync crate"*. The envelope does; the encoder does not. The whole-payload materialisation WF-11's falsifier is about happens in `crates/happenstance-core/src/event.rs`'s `mod payload`, reachable only through that crate's `serde` feature: `serialize` calls `STANDARD.encode(value)` — allocating a `String` at 4/3 the payload — and hands it to `serializer.serialize_str`, which writes the entire rendering into the output before returning. The module's own doc comment states the property and names the falsifier: *"serde's data model has no streaming entry point for a string … WF-11's falsifier is about that property, not about base64."* `crates/happenstance-sync/src/wire.rs`'s `Envelope` wraps a message in a version field and adds no second materialisation. **So the falsifier can be fired without a sync port, without a peer, and without an adapter-to-port-crate edge in this crate's graph** — which is what makes it constructible at all in a crate that is an event store and ships no sync port (`CLAUDE.md`, repository map; `project.md`, **Out of scope**).

**Decision 2 — the alternative that lost: wrapping the payload in a real `Envelope`.** It would look more like the peer the atom describes, and it would cost a dev-dependency from `happenstance-cloudflare` onto `happenstance-sync`. It is rejected on evidence rather than on taste: an `Envelope` adds a `u16` and a constant-size JSON key, so peak memory is the payload's own materialisation plus O(1). It cannot change the verdict, and it would blur the one dependency rule this workspace states twice (`CLAUDE.md`, dependency rule — `happenstance-sync` is a *port* crate whose consumers are peer adapters, and this crate is not one). If a reviewer wants the envelope shape recorded, it is recorded as this paragraph, not as an edge.

**Decision 3 — the ceiling is measured in-process, from a monotone instrument, not read off a documentation page.** `core::arch::wasm32::memory_size(0)` returns the linear memory's size in 64 KiB pages and `memory_grow(0, delta)` returns `usize::MAX` when the host refuses rather than trapping — so a staircase of grows finds the real ceiling of *this* isolate under *this* runner without aborting the process, and both are safe functions, which is not a detail here: the workspace sets `unsafe_code = "forbid"` (`Cargo.toml:101-102`) and this adapter has no escape hatch. Two properties make this the right instrument rather than a convenient one. Linear memory **never shrinks**, so `memory_size` read before and after an encode is a *high-water mark*, not a sample — the number cannot be flattered by an allocator that freed early. And a ceiling discovered by asking the host is the number the process actually hits, which is the same discipline `measured-store-limits` (HS-S0055) applies to the fixture's three `Option<usize>` ceilings and for the same stated reason (`crates/happenstance-testkit/src/contract.rs:214-279` — limits are facts, not trades).

**Decision 4 — the probe is a second test target with its own registry row, and that is forced twice over.** HS-S0054's harness is required to stay three lines and to define nothing (`../_decomposition.md`, Architecture **ARCH-AC-04**; `../every-rule-under-workerd/spec.md`, NF-006 — *"anything longer than three lines is a signal that something is being selected"*), so nothing from this story may be added to `crates/happenstance-cloudflare/tests/durable_object_conformance.rs`. And a probe whose whole job is to walk an isolate up to its memory ceiling must not share that isolate with thirty conformance rules, because a run that fails because the falsifier ran first would be a defect this story manufactured. Separate target, separate isolate, one row.

**Decision 5 — mounting means adding a row, and that points backwards at a contract.** HS-S0048's **AC-006** and HS-S0054's **AC-003** both committed that further executed wasm32 targets arrive as rows in the declared executed-target registry in `xtask/src/proof.rs` — *"the way `ARTEFACTS` takes a row"* — with no second `Step`, no second `CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUNNER` wiring and no second `--target` plumbing. This story is the second caller of that contract. **If a row is not enough, that is a finding against the seam, not a parallel step written here.**

**Decision 6 — the probed sizes are anchored on two figures already in the tree, and derived from the seeded generator already in the tree.** The floor is `MIN_SUPPORTED_EVENT_DATA_LEN` = 65,536 bytes (`crates/happenstance-core/src/limits.rs:22`; VT-21 makes it a floor every conformant store must accept, and `crates/happenstance-testkit/src/lib.rs:145` lists it among the four guaranteed minima) — the smallest payload for which "a store took it but a peer cannot forward it" is a real contradiction rather than a hypothetical. The reference size is 348,160 bytes (340 KiB), the exact subject of the measurement table in `.kb/open-questions/human-readable-payload-encoding-on-a-constrained-peer.md` and in WF-11's own clause text, so the wasm32 numbers land beside comparable host numbers instead of beside nothing. Above those, a staircase toward the measured ceiling. The bytes come from the xorshift64\* generator in `experiments/wire-format/tests/w5_payload_encodings.rs:26-42` with the same published `SEED = 0x2545_F491_4F6C_DD1D`, **re-derived in eight lines rather than depended on** — `experiments/` is deliberately outside the gate (`CLAUDE.md`, repository map), and a gate step may not import it.

**Decision 7 — the encode cost is predictable, which is what turns a staircase into a falsifier test.** Encoding P bytes to base64-in-JSON holds, at peak, the payload (P) plus the base64 `String` (≈1.333P) plus the serialiser's output buffer (≈1.333P) — roughly 3.67P before any allocator growth headroom. So the size at which the falsifier should fire is *computed* from the measured ceiling first and *then* confirmed by attempting it, rather than found by fishing. A probe that reports a failure at a size the arithmetic did not predict is reporting something else — allocator behaviour, a runner limit, a fixture leak — and the report must say which.

**Decision 8 — the negative control is the binary path on the same bytes, and it is not optional.** The atom's own table gives the expected separation: postcard 1.0000×, base64-in-JSON 1.3333×, the naive JSON integer array 3.5715×. Encoding the identical payload through `postcard::to_stdvec` in the same test, and reporting both peak-memory deltas, is what distinguishes "the human-readable path materialises and the binary one does not" from "nothing was measured". **A run whose two paths report the same cost did not exercise the encoder and its result is void** (`discover.md`, *Where the detector lives*). This is the same reasoning `the_probe_is_not_vacuous` encodes one crate over (`crates/happenstance-cloudflare/src/lib.rs:180-259`).

**Decision 9 — three admissible verdicts, and one that is inadmissible.** (a) *It fires*: at payload size S the human-readable encode fails or exhausts the isolate, with the ceiling, the peak and the failure mode recorded. (b) *It does not fire*: the largest size this runtime could be made to attempt succeeded, with H bytes of measured headroom between peak and ceiling stated as a number. (c) *Not constructible here*: the condition cannot be met on this runtime, with the exact missing element named and what would supply it. **"We did not see it fire" is not a verdict** (`discover.md`, *Questions*) — outcome (b) is only a verdict because it carries H.

**Decision 10 — nothing moves except a file in this story's folder.** No wire-format change (that is `replication-identity-and-ingest`'s, HS-P0017); no marker move and no re-scoping of WF-11 from peers to formats (same owner); no edit to `spec/SPECIFICATION.md`, whose WF-11 clause at `:2279-2313` and ledger row at `:8576` must still be resolved by `cargo xtask spec-trace`; no write anywhere under `.kb/`, because every KB write in this project belongs to `adr-0023-and-atom-resolutions` through `/redkiln:kb-ingest` and hand-authoring an atom reproduces the failure reverted at `0269720` (`CLAUDE.md`, **Where the work lives**). WF-11's two existing rules — `wire::payload_is_base64_in_json` and `wire::payload_is_raw_in_postcard` (`crates/happenstance-core/tests/wire.rs:1060`, `:1114`, held to their names by `xtask/src/proof.rs:114`) — are correct about *what* is on the wire and silent about *how much memory it took*. That silence is the gap this story fills with a measurement; it is not a defect in those rules and they are not touched.

**Decision 11 — the persona slice is the evaluator's, one remove away.** The project's three observers are the adapter author, the gate reader and the library consumer (`../_storymap.md`, Backbone), and this story serves none of them directly: it adds no API and changes no output they read. Its consumer is the **evaluator** of initiative **AC-10** — *"the evaluator can tell how strong each promise is … every clause a consumer might rely on is legibly frozen, provisional with a named falsifier, or deliberately deferred, and that state is accurate at the moment of publish"* — reached through HS-S0058, which mints the atom, and through the publish-time clause audit of DoD 12. The gate reader's only stake is that the probe *ran*: which is why it is mounted in the gate rather than in a scratch program, and why AC-007 exists.

**What this story does not decide.** The runner's shape and the fate of `.github/workflows/ci.yml`'s standalone `wasm-conformance` job (HS-S0048); the conformance target and the concurrency family's non-invocation (HS-S0054); the fixture's `Capability` constants and its three measured ceilings (HS-S0053, HS-S0055) — note that `MAX_EVENT_DATA_LEN` is a *store* limit and this story's payload sizes are not bound by it, because the falsifier is about forwarding, not about appending; ADR-0023's authorship and the atom moves (HS-S0058); the ES-32 paragraph and the CF-14/CF-27 re-reads (HS-S0057); and every question about what the wire format should become (HS-P0017).

## Data and migrations

**N/A for schema — and the reason is worth stating rather than skipping, because this story handles more bytes than any other in the project.**

No schema, no table, no `migrate()` call, no persistent data, no configuration file and no wire-format change. The probe never opens a store: it needs no `SqlStorage` handle, no `CloudflareEventStore`, no `CloudflareFixture` and no Durable Object storage, and constructing one would be a defect — it would put the store's own memory footprint inside a measurement that is supposed to be the *encoder's*. The only durable output is text in this story's backlog folder.

Two data-shaped facts are load-bearing anyway. **The payload is generated, never committed**: hundreds of kilobytes of pseudo-random bytes have no business in git, and a generated payload with a published seed is reproducible where a checked-in blob is merely present — the same argument `experiments/wire-format/tests/w5_payload_encodings.rs:7-10` makes against its own earlier draft, which cited a size with no seed and was "reproducible in form only". **The payload sizes are not bound by the fixture's `MAX_EVENT_DATA_LEN`**: that is a *store* limit, measured by `measured-store-limits` (HS-S0055) and enforced on append, while WF-11's falsifier is about *forwarding* a payload — so the probe may and should attempt sizes this store would refuse, and the report must say so explicitly to stop a later reader mistaking a deliberate over-size for a violated store limit.

Rollback is not conventional here either: nothing is deployed, and the deployment brief reaches that conclusion for the project as a whole (`../_decomposition.md`, Deployment Notes §1). The one thing that is not reversible by a revert is the *finding* — once measured, the number is knowledge, and if a later run contradicts it the response is a second measurement recorded beside the first, not a quiet edit to the first.

## Implementation notes (non-prescriptive)

- **Order is the design, not an accident.** Inside `records_the_ceiling_and_the_encode_peaks`: measure the anchored encodes **first**, while the heap is still tight and `memory_size(0)` deltas mean something; discover the ceiling **second**; attempt the computed size **last**. Growing memory is one-way, so any other order silently zeroes the peaks. A comment saying this belongs at the top of the function, or the next reader will reorder it for readability.
- **`memory_grow` returns the *previous* size, or `usize::MAX` on refusal** — it does not trap, which is exactly why it is usable as a probe under `unsafe_code = "forbid"`. Read it as a refusal signal, not as an error to unwrap.
- **Pick the writer deliberately.** `serde_json::to_vec` over a `happenstance_core::Event` is human-readable and routes `data`/`metadata` through `mod payload`'s `is_human_readable()` branch; `postcard::to_stdvec` over the *same* `Event` takes the other branch. Encoding two different values, or building the JSON by hand, breaks AC-002 and AC-005 at once.
- **Construct one `Event` and reuse it** for both paths in AC-005, so *the same bytes* is a fact about the code rather than a claim in the report.
- **Re-derive the generator; do not reach for the experiment.** Eight lines and the seed constant, with a comment citing `experiments/wire-format/tests/w5_payload_encodings.rs:26-42` as the source of the seed and the reason it is copied rather than imported.
- **The registry row's names are hand-written here, and that is the opposite of HS-S0054's choice — on purpose.** That story derived its expectation from `__emit_rule_names!` because the thing being guarded was *a harness against the rule enumeration*. There is no enumeration behind these two names; the row is a citation, which is precisely the case `xtask/src/proof.rs:25-45` argues duplication is *for* — a rename should have to be noticed.
- **`proof.rs`'s doc comment counts its targets.** Adding a row makes the count stale; correct that sentence in the same change, as HS-S0054 did before you.
- **Expect the host build to look empty.** `cargo test -p happenstance-cloudflare` will report this target as `running 0 tests` because of `#![cfg(target_arch = "wasm32")]`. That is correct and is *not* the vacuity AC-009 is about — say so in a comment.

## Risks and coupling (PR-scoped)

## Clarifications resolved during spec

1. **The AC set is exactly the ten the front half enumerated** — AC-001 … AC-010. None added, none dropped; `_ledger.md` matches one-for-one.
2. **The target's filename and its two test names are fixed here, not left to the implementer**: `crates/happenstance-cloudflare/tests/wf11_memory_ceiling.rs`, with `records_the_ceiling_and_the_encode_peaks` and `the_two_encode_paths_produce_the_published_size_ratio`. The registry row's expectations are those names **unprefixed** — there is no `mod $mod_name` wrapper because `event_store_conformance!` is not involved — and a name chosen at implementation time is a name the ledger and the row cannot both be written against in advance.
3. **Two tests, and the count is forced by the instrument.** wasm32 linear memory is one global resource shared by every test in a target and `memory_grow` is one-way, so a ceiling staircase in its own test would leave a grown heap behind and zero every later peak delta. One function therefore owns the ordering; the second is written to be order-independent (it compares encoded *lengths*, not memory) precisely so it is immune to whatever the first did.
4. **The negative control is a size comparison, not a memory comparison.** The discover stage asked for a control drawn from the atom's table; the table is a table of *sizes*. Asserting sizes makes the control deterministic, order-independent and runner-independent, where a memory-based control could be flattened by an allocator. The memory separation is still asserted, as AC-006, at the one size where 64 KiB page granularity can resolve it.
5. **65,536 bytes carries the ratio, not the peak.** At the floor anchor the base64 overhead is ≈21,845 bytes — under one 64 KiB page — so a peak-separation assertion there would be unresolvable by construction. The floor is still probed, because VT-21 makes it the smallest size at which the contradiction is real; it is AC-005 that observes it.
6. **A fired falsifier is a red gate step, and that is not resolved by shrinking the probe.** EC-003 fixes the landing shape — announce, attempt last, transcript first, escalate to the slice — because the alternative is the discover stage's second wrong implementation arriving through the back door of a green tick.
7. **The anti-vacuity mechanism's limit is stated rather than papered over.** A name-based proof artefact catches deletion, rename, `#[ignore]` and `cfg`-away; it cannot catch a body emptied while the names survive, and there is no rule enumeration here to derive an expectation from as HS-S0054 had. AC-009 therefore requires the residual gap to be **named in the report**, which is the honest form of `CLAUDE.md`'s *a rule that no adapter can fail is decorative*.
8. **The verdict is a three-variant enum in the source, not a prose convention.** *We did not see it fire* is made unrepresentable rather than discouraged, so HS-S0058 cites a choice rather than interprets a paragraph.
9. **The discover ledger's claim that the encoder lives in the sync crate is corrected, not silently worked around.** The envelope lives there; the whole-payload materialisation lives in `happenstance-core`'s `mod payload`. That correction is what makes the falsifier constructible without a sync dependency, and it is recorded in the Context pack (Decision 1) so the next reader of `discover.md` is not misled by a superseded line.
10. **Nothing here renders a surface, so §6.7/D6's composition family is empty by a signed-off decision** (`../_design.md`, N/A for the whole project, approved 2026-08-12) rather than by omission. The state family binds in the gate's output, and every applicable invariant is an AC row rather than a prose bullet.

## One-line PR slice

Implement `read` as ADR-0011's ceiling-and-page — still non-`async`, stream at the top level, ceiling captured no later than the first poll, every later statement bounded by it, no cursor held across an `await` — so ES-11's one-sample obligation, ES-12's shared sample and the port's laziness allowance all hold on a cursor Cloudflare documents as *not* a snapshot.

## Executive summary

`read` is the only method on this adapter that already has a body (`crates/happenstance-cloudflare/src/event_store.rs:148-169`), and it is the wrong body. It opens **one** cursor at the first poll and drains it across every later poll — precisely the shape Cloudflare says gives no stable snapshot — and then tries to notice the damage afterwards with `check_cursor_still_valid` (`:292-306`), which detects a torn read rather than preventing one. Under it, `render_read` (`:308-314`) and `decode_row` (`:316-319`) are `todo!()`.

This PR replaces the mechanism with the one an accepted atom already prescribes: capture a position ceiling *H* no later than the first poll and bound every statement after the first by `position <= H` (or `>= H` under `backwards`), re-`exec`-ing a bounded page instead of holding one cursor across suspension points (`.kb/decisions/0011-read-laziness-and-isolation.md:69-75`). That single mechanism discharges **ES-11** and **ES-12** together — they reduce to ES-10 plus a ceiling (`spec/SPECIFICATION.md:2959-2963`) — and it is the mechanism the long-form record names this exact adapter as the falsifier of if it cannot be afforded (`references/adr/0011-read-laziness-and-isolation.md:423-428`).

The delta is bounded to the read path: `render_read` gains the ceiling and renders the DCB query, `decode_row` decodes a row into a `SequencedEvent`, `StreamState` gains the states paging needs, and the crate's own documentation stops describing the cursor as an unresolved trade. **No `append`, no `head`, no `contains_event_id`, no fixture, no conformance target, no `Cargo.toml`.** Those are the slice-mates' and the next milestone's.

## Context pack

**Decision 1 — the mechanism is already decided, and this story implements it rather than re-opening it.** `.kb/decisions/0011-read-laziness-and-isolation.md` is **accepted and immutable**, and its operative sentence is unambiguous: *an adapter issuing more than one statement per `read` must capture a position ceiling no later than the first poll and bound every later statement by it* (`:69-75`). The crate's own docs (`crates/happenstance-cloudflare/src/lib.rs:96-107`) still frame this as an open choice between "buffer everything" and "a snapshot only until the first `await`". That framing predates the atom. Ceiling-and-page is the resolution; buffering the whole result set and the weaker promise are the two alternatives that **lost**, and neither may be adopted here without a new decision record (`../_decomposition.md` Architecture Notes §2, ARCH-AC-03). Project AC-007 lists *honoured* first for the same reason.

**Decision 2 — the referent for "laziness" in the older prose is wrong, and the clause wins.** `crates/happenstance-cloudflare/src/lib.rs:100-107`, `project.md` AC-007(a) and `_storymap.md` all say *"ES-9's laziness requirement"*. ES-9 is `from` **names a position, not an index** and is `[FROZEN]` (`spec/SPECIFICATION.md:2748-2762`). The clause that actually carries the sample obligation is **ES-11 — A read is a snapshot** (`:2926-2932`), `[PROVISIONAL]`, joined by **ES-12 — All items of one `Query` share one snapshot** (`:2998-3003`), also `[PROVISIONAL]`. And ES-11 does **not** require laziness: *"laziness is therefore permitted and never required, and building a stream and never polling it is not guaranteed to be free"* (`:2943-2951`). Both project.md and _storymap.md state that where a brief and a clause disagree the clause wins; this is that case. Implement against ES-11/ES-12 and correct the referent in the crate docs as part of this diff.

**Decision 3 — this adapter is a *named falsifier* of the two clauses it is implementing, so "it cannot be done here" is a reportable outcome and not a private judgement.** ES-11's falsifier is named as *"a cursor-based adapter that cannot hold a stable snapshot across an `await` and cannot afford the ceiling either — the Durable Object, **phase 9**"*, and ES-12's is the same adapter emitting one statement per `QueryItem` (`references/adr/0011-read-laziness-and-isolation.md:423-428`, `:715`, `:801-802`). If ceiling-and-page holds, the falsifier does not bite here and the clauses survive contact with the shape they were most at risk from. If it does not, that is **evidence for a decision record and a re-plan**, escalated with the compiled reason as ADR-0023 material — never a silently declined capability and never a quietly weakened promise. Initiative DoD 12 audits every provisional clause's falsifier at publish, so the outcome is read either way.

**Decision 4 — the shape of `read` is a binding constraint, not a style preference.** `read` stays a **non-`async`** method returning `impl Stream` at the top level with **no `+ Send`** (`crates/happenstance-cloudflare/src/event_store.rs:148-152`). Nesting the stream inside a future silently drops `+ Send` from the derived flavour and defeats the whole two-trait design (`CLAUDE.md` constraint 3; ADR-0001, ADR-0008). The two tests in `crates/happenstance-core/src/memory.rs` that pin this — `send_flavour_stream_is_send_in_generic_code` and `spawns_from_generic` — are out of this story's boundary and must both stay green; `spawns_from_generic` is the one that rejects an `async fn read` refactor. Here the shape costs nothing: `SqlStorage::exec` is **synchronous** (`crates/happenstance-cloudflare/src/sql_storage.rs:7-12`), so there is nothing to await before a cursor exists.

**Decision 5 — the state machine stays hand-written, and that is why paging is expressible at all.** `SqlRowStream`'s `poll_next` is written by hand precisely so its `Send`-ness is decided by its **fields** rather than inferred from a coroutine (`event_store.rs:198-204`, `../_decomposition.md` Architecture §1 seam table). A generator (`async_stream::stream!`) would be the natural way to write a chunked-cursor read and is exactly what ADR-0011 refused to forbid by declining an `Unpin` bound (`references/adr/0011-read-laziness-and-isolation.md:448-464`) — but here the hand-written machine is load-bearing for the `!Send` probe at `crates/happenstance-cloudflare/src/lib.rs:229-232`, which asserts `SqlRowStream` is `!Send`. Add states; do not convert the machine.

**Decision 6 — `ReadOptions::to` and the internal ceiling *compose*; they are not alternatives.** `to` is the caller-side spelling of a window and is **inclusive** (`crates/happenstance-core/src/query.rs:277-282`, `:322-330`); the ceiling is the adapter's internal bound. The effective upper bound is the tighter of the two, and under `backwards` `from` remains the higher bound and `to` the lower (`query.rs:277-282`). `ReadOptions::to`'s own doc states the trap in the caller's direction — *one `read` is one sample; n chunked reads are n samples* — and the adapter's paging must not make that true **inside** one `read`.

**Decision 7 — `limit` truncates matches, not scanned rows, and `limit(0)` yields nothing.** `ReadOptions::limit` is `Option<usize>` and `Some(0)` reads none, deliberately diverging from the DCB reference implementation's falsy-zero reading (`crates/happenstance-core/src/query.rs:286-288`, `:334-340`). Paging must therefore consume the caller's limit against **matched** rows only — a page that scans rows a query item excluded must not spend the budget (`crates/happenstance-testkit/src/lib.rs:143`). `read_limit_applies_after_filtering`, `read_backwards_limit_applies_after_filtering` and `read_limit_zero_yields_nothing` are the rules that observe it (`crates/happenstance-testkit/src/registry.rs:126-137`).

**Decision 8 — the empty store is the documented failure mode of the mechanism this story adopts.** On an empty store `head()` is `None` (ES-30), and a ceiling computed as arithmetic on that bound errors or panics on a store whose only fault is being new — *the state every adapter is in on its first run* (`spec/SPECIFICATION.md:2952-2958`; `references/adr/0011-read-laziness-and-isolation.md:374-384`). `NullHeadPagingStore` is the registered adapter that fails `reading_an_empty_store_yields_nothing` for exactly this. A read against a store with no rows must yield an empty stream and **no error**, with the read options exercised against it rather than short-circuited.

**Decision 9 — a live read stream must not block an append, and a re-entered object must not panic.** A Durable Object is single-threaded but **re-entrant** (`crates/happenstance-cloudflare/src/sql_storage.rs:20-23`): a second future can be created and polled while the first is suspended. `a_live_read_stream_does_not_block_an_append` is the rule (`crates/happenstance-testkit/src/registry.rs:210`, clause ES-36 at `spec/SPECIFICATION.md:4178-4196`), and `spec/SPECIFICATION.md:4235-4250` records a third obligation stated by **no** clause: a `read` issued while an `append` on the same handle is suspended must complete. A stream holding a `RefCell` borrow, or a live cursor, across a suspension point is the adapter that hangs. `SqlCursor` already re-borrows on each advance rather than holding a `Ref` (`sql_storage.rs:196-199`) — preserve that discipline through the real bindings, and report re-entrancy as `SqlError::AlreadyBorrowed` rather than panicking in `borrow_mut` (`:102-109`).

**Decision 10 — the read must not truncate a position on the way out.** Workers SQL widens integers through a JS number, so a stored position above 2^53 is not round-trippable even though `SequencePosition` is a `NonZeroU64` (`crates/happenstance-cloudflare/src/lib.rs:108-112`; `sql_storage.rs:40-42`). `decode_row` is in this story's diff, so the read side of that fact is this story's: an unrepresentable position is an **error item on the stream** (`CloudflareEventStoreError::StoredPosition`, `event_store.rs:135-142`), never a silently narrowed value. The *declared limit*, its reporting on the write side and the boundary as the suite observes it belong to `durable-object-write-path` and `measured-store-limits` (`_storymap.md:118`) — do not mint a second answer for them here.

**Decision 11 — no rule may assert on literal position values, and none is added here anyway.** The specification permits gaps and a conformant adapter may leave them; asserting `[1, 2, 3]` converts a MAY into a MUST without an ADR (`CLAUDE.md`, *The rule that matters*; CF-6, enforced by `xtask/src/lints.rs`). This story adds **no** conformance rule: the read family already exists (`crates/happenstance-testkit/src/registry.rs:124-138`, `:210`, `:213`) and this story's job is to *satisfy* it. Any crate-local test written here compares against positions the store actually assigned.

**Decision 12 — the persona slice.** The observer here is the **adapter author** from the story map's Backbone (`_storymap.md:24-31`, activity **B** — *store and replay events inside a Durable Object*): the person who must be able to point at `crates/happenstance-cloudflare/src/event_store.rs` and find `read` with no `todo!()` under it, and get back a replay that is one sample rather than a moving target. The **gate reader** sees this story only through the milestone it merges with; the library consumer sees nothing, because this story adds **no public API surface** — every item it touches is already `pub` and already signed off as shape (`event_store.rs:145-196`).

**What this story does not decide.** The SQL rendering strategy is genuinely open and is ADR-0023's material, not this spec's: one statement or a bounded page per query item, whether tags AND-within-an-item is a join on `event_tag` or a filter over the `tags` blob, and how the ceiling is captured — `max(position)`, `head()`, or a column returned alongside the first page (`../_decomposition.md` Architecture Notes §6, `:429-437`). What is *not* open is that the ceiling exists and bounds every later statement.

## Data and migrations

**N/A for schema; read-only against the schema a slice-mate creates.** This story issues `SELECT`s and no DDL and no writes. `CloudflareEventStore::migrate` — schema *creation* for a fresh Durable Object, not a backfill, since nothing has ever written through this adapter — belongs to `durable-object-write-path` (`crates/happenstance-cloudflare/src/event_store.rs:79-86`; `../_decomposition.md` Deployment Notes §1, *Migration / backfill*). There is no prior schema version, no deployed data and nothing to roll back.

Two dependencies on that schema are load-bearing here and are named so the two stories agree rather than collide. First, the `event` / `event_tag` shape the module doc sketches (`event_store.rs:8-28`) is what `render_read` renders against, and whether tags are matched by a join on `event_tag` or by filtering the `tags` blob is an open rendering choice this story may make and must record (`../_decomposition.md` Architecture Notes §6). Second, the schema gains the `origin_store` and `origin_position` identity columns that the doc block predates (`event_store.rs:187-195`); the read path does not require them for `SELECT`, but `decode_row`'s column list must match whatever the migration actually creates — a `RowShape` error is the designed report for a disagreement, and it is a signal that the two halves of the slice drifted, not a condition to code around.

Seeding for this story's own tests may go through the slice-mate's `append` where it has landed, or directly through `SqlStorage::exec` where it has not; the second keeps the two stories separable and is the honest fallback. Either way the tests compare against positions the store actually assigned, never literals (`CLAUDE.md`, *The rule that matters*; CF-6).

## Implementation notes (non-prescriptive)

Latitude first: **how** the ceiling is captured is open and is ADR-0023's material, not this spec's (`../_decomposition.md:424-442`). `max(position)` in its own statement, `head()`, and a value returned alongside the first page are all admissible; so is one statement per query item versus a bounded page per item, and so is matching tags by a join on `event_tag` versus filtering a `tags` blob. What is **not** open is that a ceiling exists, that it is captured no later than the first poll, and that every later statement is bounded by it. Record the choice and the alternative that lost in the implementation report — that record is what HS-S0058 stages into `.kb/_intake/`.

A few things worth knowing before starting, each of which has already cost someone time in this tree:

- **There is nothing to await before a cursor exists.** `SqlStorage::exec` is synchronous (`crates/happenstance-cloudflare/src/sql_storage.rs:7-12`), so keeping `read` non-`async` costs nothing here. The suspension points are the caller's, between polls — which is exactly why the cursor must not span them.
- **`check_cursor_still_valid` (`event_store.rs:292-306`) is a detector, not a mechanism.** It notices a torn read after the fact. Deleting it is fine; keeping it as an explicitly belt-and-braces assertion beside the real mechanism is also fine. Leaving it as the primary defence is the one thing ARCH-AC-03 forbids.
- **Extend `StreamState`; do not convert the machine.** The states paging needs are roughly: not started → ceiling captured, page in hand (with the last position yielded) → page exhausted, re-`exec` under the ceiling → done. A generator (`async_stream::stream!`) is the natural spelling and ADR-0011 deliberately declined an `Unpin` bound so it would stay legal (`references/adr/0011-read-laziness-and-isolation.md:448-464`) — but here the hand-written machine is what makes `SqlRowStream`'s `!Send`-ness a property of its *fields*, which is what the probe at `lib.rs:229-232` asserts.
- **Spend the caller's `limit` on matches only.** The easiest wrong implementation is a page size that doubles as the limit: a page that scans ten rows and matches two must consume two units of budget, not ten. `limit_applies_across_items_not_per_item` is the rule that finds the other version of this mistake.
- **Under `backwards`, every bound flips but `to` stays the lower one.** The ceiling becomes a floor (`position >= H`), `from` is the higher bound and `to` the lower (`crates/happenstance-core/src/query.rs:277-282`). This is the branch where "the tighter of the two" is easiest to get backwards.
- **Seed tests through whichever path exists.** If the slice-mate's `append` has landed, use it; if not, `SqlStorage::exec` directly keeps the two stories separable. Either way, capture the positions the store assigned and compare against those.
- **Write the negative controls as you go.** AC-003, AC-005 and AC-006 each name one. A rule no adapter can fail is decorative (`CLAUDE.md`), and the ceiling-less paging read is the specific wrong implementation this story exists to not become.

## Clarifications resolved during spec

1. **The AC set is exactly the front half's seven.** AC-001…AC-007 as handed over; none added, none dropped. The ledger carries the same seven.
2. **"ES-9's laziness requirement" is a wrong referent in three inherited documents**, and this spec does not propagate it. `crates/happenstance-cloudflare/src/lib.rs:100-107`, `../project.md` AC-007(a) and `../_storymap.md`'s one-line slice all name ES-9; ES-9 is `from` naming a position rather than an index and is `[FROZEN]`. The obligations this story discharges are **ES-11** and **ES-12**, and ES-11 explicitly does *not* require laziness. Both `project.md` and `_storymap.md` state that the clause wins where they disagree with one, so this is resolved rather than escalated — and correcting the crate's prose is inside this PR's boundary. The story map's row text is left as written; it is a planning artifact, not a normative one.
3. **The "recorded verdict, either way" is folded into AC-003 rather than given its own row.** Project AC-007's own wording is a disjunction — *honoured, or reported as a declined capability with a reason, or the clause amended by decision record* — so the escalation is part of the same criterion, not a separate one. This keeps the seven ids stable while leaving nothing unowned.
4. **The composition family of interaction quality is N/A, and that is a finding rather than a skip.** `../_design.md` is signed off with `## Surfaces` = *N/A*, `## Items` and `## Signatures` empty, and the project's briefs table leaves `ux` unchecked. The state family is mapped onto the stream and the error type instead, and every mapped invariant is carried by an existing AC row — none is stated only in prose, because a bullet there would never be gated.
5. **No conformance rule is added, and the negative controls live in this crate.** The read family already exists and already rejects the ceiling-less paging store, so a new rule would be one no adapter can fail. The three negative controls this story owes (ceiling-less paging, a cursor held across a poll, ceiling arithmetic over `head() == None`) are written in `crates/happenstance-cloudflare/`'s own tests.
6. **The unit tier's target is inherited as open, not settled here.** The Testing brief flags that `cargo test -p happenstance-cloudflare` may stop linking on the host once `worker` lands (`../_decomposition.md:594-624`). This spec does not decide it; it constrains the tests so they can move behind `wasm_bindgen_test` without being rewritten, and inherits the brief's standing obligation that the assertions stay reachable from an ordinary `cargo test`.
7. **`crates/happenstance-cloudflare/tests/` does not exist yet**, so this story's tests are an in-crate `#[cfg(test)]` module in `src/event_store.rs` rather than an integration target. That matches how the existing `!Send` probes are organised and keeps the conformance target — which *is* an integration target — unambiguously `every-rule-under-workerd`'s to create.

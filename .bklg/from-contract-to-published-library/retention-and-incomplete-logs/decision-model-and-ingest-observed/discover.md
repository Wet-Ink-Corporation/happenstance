## Questions

- **Is "fails loudly" expressible in the existing error vocabulary?** **Answered here — this is the story that answers it empirically, and the answer is no.** Both readers fail *silently*, and the silence is the finding. `read_decision_model` returns `(Vec<SequencedEvent>, Option<SequencePosition>)` with no channel for completeness (`crates/happenstance-core/src/store.rs:321-331`), so a caller receives a well-typed, confidently wrong fold; `AppendCondition::after_opt` then accepts that position without complaint and `Guard::is_violated_by`'s two-arm `match` admits the append (`crates/happenstance-core/src/append.rs:249-252`). `IngestStore::holds` returns `Result<bool, _>` (`crates/happenstance-sync/src/ingest.rs:164`), in which `false` conflates *"never had it"* with *"minted it, acknowledged it, and forgot it"*. Neither reader has a variant, a flag or a return shape that could carry the distinction. **This is precisely the collision with the no-surface-change constraint the intake brief predicted** (`_intake-brief.md:64-67`), and this story's obligation under AC-006's second sentence is to record it with the missing surface named — DA-7's option table (`_decomposition.md:363-379`) — and to make no change. The escalation is HS-S0124's; the finding is this story's.
- **DT-7 — one signal or three?** **Deferred to HS-S0120**, which depends on this story precisely so it inherits evidence rather than intuition. What to record for it: whether the two readers' wrong outputs differ between the suffix and the scattered configuration. If a wrong fold looks identical under a benign prune and a regulated purge, that is a direct argument that a three-way distinction has no channel to be reported through — which is DT-7's real cost side.
- **How is an observation recorded so it is evidence and not a claim?** **Deferred to `spec`, with the constraint fixed:** the artefact captures the actual returned value — the fold's contents, the `Option<SequencePosition>`, the boolean, and the admitted-versus-rejected outcome of the follow-up append — against the positions the store actually assigned, and it is reproducible by a committed command. A prose sentence describing what would happen fails DR-6 on its own terms.
- **What if HS-P0017 has not landed the ingest write path?** **Answered:** run the ingest half against whatever seam HS-P0017 actually delivered, and **record the gap** (`_decomposition.md:565-570`). `holds()` has a real body and is the interesting method regardless, so the DA-8 observation is reachable even with the write path still `todo!()`. A stubbed ingest is not available: it would demonstrate a hazard against a reader nobody ships.
- **Does this story settle `read_from_a_gap_position`'s ownership?** **Explicitly no, deferred and fenced.** The gap-read neighbourhood is one clause away and its narrative will look like this story's subject while it is being written (`_decomposition.md:556-560`; `project.md:124-127`). Ownership is HS-S0121's narrowed successor atom, and this story must not resolve it in passing.

## Decision

The failure this project exists to catch is a reader that quietly builds a wrong answer from a truncated log, and until now nothing could stage it because every store in the workspace holds its whole log. This story runs two real readers — both already in the tree, neither written for this purpose — against HS-S0114's instrument and records what they actually do: `read_decision_model` returns the last *retained* match, whose position feeds `AppendCondition::after_opt`, so a conditional append is admitted where the destroyed history would have rejected it; and `IngestStore::holds` answers `false` for an event this very store minted and acknowledged, so a peer re-sending on `false` re-sends forever. The spec will cover: the two observation harnesses and where they live; the retained configurations each is run under, so a benign prune and a scattered purge are both exercised; the exact values captured — the fold, the `Option<SequencePosition>`, the boolean, and the admitted/rejected outcome of the follow-up append — compared against positions the store actually assigned; the committed command that reproduces them; and the written finding that neither reader fails loudly, naming the missing surface from DA-7's option table and recording it against AC-011 for HS-S0124 to escalate, with no change made to any published signature.

## The wrong implementation

**`ConfidentFoldReader` — a decision-model read that treats a truncated log as a complete one and returns a confidently wrong fold.** It is not a mutant someone has to write: it is `happenstance_core::read_decision_model` as it exists at `crates/happenstance-core/src/store.rs:321-331`, run against a store that has forgotten. It passes **every** test in the workspace, because every store in the workspace holds its whole log — and its output is not merely wrong, it is well-typed, plausible and accompanied by a position that the append path will accept. The follow-up conditional append is then admitted where the destroyed history would have rejected it, which is E2E-47 in miniature and ES-40's `Rejects:` verbatim (`spec/SPECIFICATION.md:4373-4379`). **Its home is this story's own observation harness under `crates/happenstance-testkit/tests/` (or the sibling target HS-S0114 created), captured as the actual wrong value** — the fold's contents and the admitted append — not as a note that something failed, per `mutation_coverage.rs`'s own discipline against tests that record only that a thing went red. Its ingest twin is `HoldsSaysFalse`: `IngestStore::holds` returning `false` for an `EventId` this store minted, which is `contains_event_id`'s reduction (*"if the identifier's store half is its own incarnation, the question reduces to whether that position exists"*, `crates/happenstance-core/src/store.rs:256-263`) being exactly wrong under forgetting.

Two ways this story could satisfy AC-006 on paper and prove nothing:

- **A reader run only from the instrument's own first retained position.** A suffix store read from where it starts retaining never crosses the hole, so the fold comes back complete-looking and the observation is vacuous. Both readers must be pointed at a query and a `from` that span the gap — and DA-1's scattered configuration exists so that survivors sit *below* the hole, which a suffix-only run can never produce.
- **A "loud failure" that is a log line.** Emitting `warn!("history may be incomplete")` from the harness, or writing "the reader fails loudly" into the report, satisfies a reader of the report and nothing else: the caller still receives a `bool` and a `Vec` and cannot branch on either. Loudness that the caller cannot act on is not loudness. The honest outcome here is the negative one — recorded, with the missing surface named — and AC-006's own second sentence makes that a pass.

Standing constraint, restated because this story is where a reader would most like a convenient handle: **the instrument is an instrument first and a target never** (`project.md:141-145`). Nothing here promotes it out of `crates/happenstance-testkit/tests/` or exposes it from any of the three publishable crates in order to make an observation easier to run.

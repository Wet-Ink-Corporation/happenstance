## Questions

- **Is "fails loudly" expressible in the existing error vocabulary?** **Answered, and by this story's dependencies rather than by assertion: no.** HS-S0118 recorded a confidently wrong fold and a `holds()` that says `false` for an event the store minted; HS-S0119 recorded a runner that stalls with no error anywhere; HS-S0115's pass list enumerates every rule that cannot tell the two stores apart. Nothing in the port carries the distinction — `Guard::is_violated_by` is a two-arm `match` (`crates/happenstance-core/src/append.rs:249-252`), `read_decision_model` has no completeness channel (`crates/happenstance-core/src/store.rs:321-331`), `contains_event_id` returns `Result<bool, _>` (`:268`). **The consequence for this story is structural, not incidental**: because every candidate primitive is a port surface (DA-7's four rows, `_decomposition.md:363-379`) and gate decision 4 forbids changing one, the branch reachable here is the **reasoned refusal** — stated in terms, with the instrument as its illustration, and with the option set named so that a future `0.3.0` inherits a decision rather than a rediscovery. If the ADR's author concludes otherwise, that is an AC-012 escalation raised through HS-S0124, not a change made here.
- **DT-7 — one signal or three?** **Answered upstream by HS-S0120 and *recorded* here.** This story does not re-open it; it carries the resolution and its named loser into ADR-0028 so the decision and its record agree. Same for AC-010's redaction answer, which HS-S0120 settles and AC-010 requires to appear in the ADR.
- **Is ADR-0028 one question?** **Answered: yes, and the runbook already phrases it** — *"What is a store permitted to forget, and how does it say so?"* (`RUNBOOK.md:307`). The temptation is a second question — *how should a store report it* — which is ES-39's primitive and precisely what the constraint excludes; keeping it out is what keeps this one ADR rather than two (`RUNBOOK.md:264-268`).
- **Can the ingest wave express a mutation of an existing `open_question` atom?** **Deferred to `spec`, with the failure mode pre-declared.** DA-6's shape is three artifacts: ADR-0028; a **narrowed successor** `open_question` carrying only the `read_from_a_gap_position` thread; and the original moved to `superseded` with `related` naming both, plus the bullet update on `.kb/maps/open-questions-index.md`. If `/redkiln:kb-ingest` cannot express the third as a mutation, **that is a finding to report — not grounds for hand-editing `.kb/`**, which is what the revert at `0269720` exists to prevent (`_decomposition.md:356-361`).
- **Operational hazards in running the wave?** **Answered:** the intake glob picks up the intake directory's own README — drop it at the approval gate — and the wave id is suffixed so it does not overwrite an earlier wave's audit trail (`_decomposition.md:358-361`).

## Decision

This is where the project's answer is written. One question — what is a store permitted to forget, and how does it say so — answered on the evidence four stories produced: the enumerated pass list that says which rules cannot tell a pruned store from a young one, two named rules and their mutants, and three readers observed failing silently rather than loudly. Because every primitive ES-39 contemplates is a change to a port published at `0.2.0`, and gate decision 4 constrains this project to what needs no such change, the branch reachable here is the reasoned refusal — which the runbook has always held to be a legitimate answer and which DR-9 makes no cheaper, since the refusal still owes the instrument and the illustration. The spec will cover: the long-form record under `references/adr/` carrying the pass list, the reader observations and the rejected alternatives; the atom staged in `.kb/_intake/` and landed by `/redkiln:kb-ingest`, never hand-written; the alternatives named as losers, including `earliest_position()` and why a floor is the wrong *shape* for a purge that is scattered rather than a prefix; DA-1's widening of CF-27's wording recorded with its reason; CF-25/CF-26's residual exposure recorded **open**, not implied closed; SY-32 cited by id with ADR-0026/ADR-0027 untouched; DT-7's and the redaction question's resolutions carried in from HS-S0120; and the three-artifact open-question wave — the answer, a narrowed successor question keeping `read_from_a_gap_position` open, and the original moved to `superseded` — with `redkiln validate --kb` and `redkiln doctor` clean.

## The wrong implementation

**`RefusalByOmission` — an ADR-0028 that declines to add a port surface, says so in a sentence, and stops.** It satisfies every existing check: the atom has valid `KbFrontmatter`, `redkiln validate --kb` is clean, `cargo xtask spec-trace` is green because the markers moved, and the project's Definition of Done reads as met. It is wrong because a refusal that does not say what it is refusing to protect the reader *from* is indistinguishable from never having looked — and this project ran the experiment precisely so the difference would be visible. DR-9 states the obligation (`project.md:174-176`): *"deletion is out of scope for `EventStore`, and here is what a deleted-from store looks like to a reader"* — the instrument and the three recorded observations are the second half of that sentence and are not optional under the refusal branch. Its close relative is **`RefusalOnSchedule`**: the same document, chosen because this is rank 5 at the end of the initiative, where *"refuse it" stops being a decision and becomes the default* (`project.md:331-335`). It will be visible in the reasoning, and the defence is that the losers are named with their arguments rather than merely listed.

Three more that pass everything and lose something real:

- **`AtomByHand` — ADR-0028 written straight into `.kb/decisions/`.** It validates, it reads correctly, and it produces the directory layout of the process without the process. This is not a hypothetical: it was done once and reverted at `0269720`, and `CLAUDE.md` cites that revert as the recorded cost. The check is provenance — the atom came through `.kb/_intake/` and `/redkiln:kb-ingest`.
- **`WithdrawTheWholeAtom` — resolving `es-38-and-gap-read-rules-are-unowned` by flipping its `status` and moving on.** `redkiln validate --kb` is clean, AC-015's letter is met, and `read_from_a_gap_position`'s ownership — a thread this project explicitly does not own (`project.md:124-127`) — has been closed in passing by an atom that never mentioned it. The defence is the narrowed successor atom, which is why DA-6's wave is three artifacts and not one.
- **`SY32Restated` — an ADR-0028 that re-derives the retention-gap answer instead of citing it.** It reads as thorough and creates a second source of truth for a decision another project owns, which is exactly the drift AC-016 forbids. The check is that the ADR cites SY-32 by id and that this project's diff does not touch ADR-0026 or ADR-0027.

This story registers no conformance mutant, because it adds no rule. Its executable checks are `redkiln validate --kb` — including the accepted-decision immutability check against `HEAD` — and `redkiln doctor`; everything else is checked by reading the atom against the four criteria above.

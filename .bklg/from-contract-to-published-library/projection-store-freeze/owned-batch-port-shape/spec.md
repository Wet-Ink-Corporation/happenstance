## One-line PR slice

Land §4.0's trait verbatim in `crates/happenstance-core/src/projection.rs` — `type Batch;` with no lifetime, non-`async` infallible `begin`, `Checkpoint` / `Authority` / `CommitError` / `ResetError`, `reset` — re-export the four new types from the contract crate's export block at `crates/happenstance-core/src/lib.rs:98-124`, and restate every downstream skeleton signature with the same `Batch` type, the same `Error` type and the same `todo!()` bodies, recorded as a reviewed diff.

## Executive summary

This PR changes the **shape of the port**, and nothing else. It is the first story in slice `projection-port-and-probe` and the first code in the project: the three decision atoms and the API design record land before it (`depends_on`), and the write seam, the reference store and the whole conformance suite land after it.

Delta against the tree as it stands:

- `crates/happenstance-core/src/projection.rs` (139 lines today) gains four public types and one method and loses a generic associated type. Against today's trait at `projection.rs:87-139` the diff is **five** changes, not one — the batch lifetime, `begin`'s signature, `checkpoint`'s return type, `commit`'s parameter list and error type, and `reset` as a new method (Architecture brief Note 7, `_decomposition.md:579-604`).
- `crates/happenstance-core/src/lib.rs:115` gains `Checkpoint`, `Authority`, `CommitError`, `ResetError` beside `ProjectionId, ProjectionStore, SendProjectionStore`. No new feature gate: the `conformance` feature belongs to the slice-mate `projection-probe-conformance-feature`, and `unstable-projection` belongs to `unstable-projection-gate-and-clause-disposition`.
- **Five** `ProjectionStore` impls across **four** adapter crates are restated. The briefs name three crates (Postgres, Ladybug, SQLite); `crates/happenstance-neon/src/projection_store.rs:153` is a fifth impl the seam map's skeleton row omits, and it carries a rendered doctest (`projection_store.rs:92-93`) and a `+ 'static` bound the GAT forces (`:141-152`). That gap is reported here rather than discovered during implementation.

What this PR deliberately does **not** land: any conformance rule, any probe, `MemoryProjectionStore`, any maturity-marker edit, and any verdict on whether the port is frozen. It makes those buildable; it proves nothing about them. A green gate here is a precondition for DoD 7, never a contribution to it (`project.md` "Definition of done", item 8).

### The shape is specified, not designed here

`spec/SPECIFICATION.md:4642-4720` is a fenced Rust block giving the target trait and its four supporting types in full. **Land it verbatim.** Where this spec and the specification disagree, the specification wins (`_decomposition.md:277-279`, quoting `_intake-brief.md`'s intake gate). The concrete deltas against `crates/happenstance-core/src/projection.rs:87-139`:

| Today | Target | Clause |
| --- | --- | --- |
| `type Batch<'a> where Self: 'a` (`projection.rs:97-99`) | `type Batch;` — owned, no lifetime | PS-5 (`spec/SPECIFICATION.md:4868-4883`) |
| `async fn begin(&self) -> Result<Self::Batch<'_>, Self::Error>` | `fn begin(&self) -> Self::Batch` — neither `async` nor fallible | PS-6 (`:4884-4897`) |
| `checkpoint → Result<Option<SequencePosition>, E>` | `checkpoint → Result<Checkpoint, E>` | PS-19, PS-24 (`:5218-5249`, `:5330-5352`) |
| `commit(batch, id, position) -> Result<(), E>` | `commit(batch, id, position, Authority) -> Result<(), CommitError<E>>` | PS-15, PS-21, PS-22, PS-24 |
| — | `reset(batch, id) -> Result<(), ResetError<E>>` | PS-16 – PS-18 (`:5172-5217`) |
| `rollback(batch: Self::Batch<'_>)` | `rollback(batch: Self::Batch)` — stays on the port | PS-8 (`:4911-4925`) |

Four decisions inside that block are load-bearing and each has a reason a reviewer will otherwise re-litigate:

- **`Checkpoint` is a three-variant enum, never `(Option<SequencePosition>, bool)`.** The tuple can spell `(None, true)` — "authoritative, never run — which means nothing". The port's rustdoc carries that sentence where the reader meets `checkpoint`, once (UX brief AC-U03, `_decomposition.md:112-119`; `standards/rust/70-rustdoc-obligations.md` RS-70-5).
- **`CommitError` and `ResetError` stay two enums, not one `ProjectionError<E>`.** `commit`'s caller must not have to consider `Refused`, which `commit` cannot produce; `#[non_exhaustive]` already forces a wildcard arm without also forcing dead ones (`spec/SPECIFICATION.md:4722-4727`). Each carries the adapter's error as a **type parameter**, never a `String` (`standards/rust/30-error-taxonomy.md`). The precedent is `AppendError` at `crates/happenstance-core/src/error.rs:186-193`.
- **`begin` is infallible on purpose, and this is not symmetry-tidying to undo.** `async` + fallible *implies a round trip* that Neon's one-shot HTTP transport cannot afford and does not need (`spec/SPECIFICATION.md:4884-4897`; Architecture brief Note 9). Do not "improve" it back for symmetry with `EventStore`.
- **`reset` takes the caller's own batch of deletes**, because the port has no idea what the read model is (`spec/SPECIFICATION.md:5165-5170`). It is `commit`'s dual: `commit` moves the checkpoint to `Live`/`Rebuilding`, `reset` moves it to `NeverRun`, same transaction, same atomicity.

`ResetError::Refused` carries no payload today (`spec/SPECIFICATION.md:4676-4682`). Whether it gains the store's stated reason is **`_design.md`'s call, taken by the dependency story `projection-api-design-record`** (UX brief AC-U07, `_decomposition.md:148-157`). Implement what that record says; if it is silent, that silence is the failure and this story reports it rather than choosing.

### Dropping the lifetime does not close the foreign-batch hole

`b.commit(a.begin())` type-checks today and will still type-check after this change. Tying the batch to the receiver's lifetime **was compiled and refuted** — a lifetime names a region, not an instance, and two `&Store` references unify to a common region (`spec/SPECIFICATION.md:5099-5125`). The only type-level fix is a generative brand, which fights `async` and forbids the batch escaping a closure, defeating the caller the hazard is about. So PS-15 stays `[PROVISIONAL]` and is discharged **at run time**: `begin` stamps an identity minted per store instance and `commit` compares. With an owned batch the stamp is a field and the check is an integer comparison. This story lands the `ForeignBatch` variants on both error enums and the doc that says how they are discharged; the rule that exercises them is `commit-rollback-and-drop-rules`.

### Both flavours, and the bound that cannot be written

`projection.rs:87` carries `#[trait_variant::make(SendProjectionStore: Send)]` and **keeps it** (ADR-0001, `.kb/decisions/0001-async-port-flavours.md`; CLAUDE.md binding constraint 1). Two consequences:

- `type Batch: Send;` **cannot be written.** `trait_variant` copies associated-type bounds verbatim into the `!Send` flavour, which would break `wasm32` (PS-36, `spec/SPECIFICATION.md:5601-5627`). The `Send` flavour transitively requires `Batch: Send` and the port must *document* that rather than enforce it.
- Generic code binds `ProjectionStore`, the weaker requirement, never `SendProjectionStore` — and imports only one of the two names per module, because both in scope makes method calls ambiguous (CLAUDE.md binding constraint 4).

The owned batch is what makes the caller-side bound writable. `crates/happenstance-ladybug/tests/port_shape.rs:33-70` currently spells it `for<'a> S::Batch<'a>: Send` and records that rustc's own suggestion does not compile as printed; under `type Batch;` it becomes `S::Batch: Send`, "which a caller might write without help". That test is the measurement of PS-5's benefit and it must survive this change as a test that can still fail.

### AC-013's bar is about the adapters' own choices, not the diff's size

Every skeleton's method signatures must be restated — the port changed by five things, so a mechanical restatement is forced. **The bar is: same underlying `Batch` type, same `Error` type, same storage strategy, same `todo!()` bodies** (`_decomposition.md:592-604`). `PostgresProjectionStore` keeps `Transaction<'static, Postgres>`; `LadybugProjectionStore` keeps `GraphWriteSet`; `SqliteProjectionStore` keeps `SqliteBatch`; `NeonProjectionStore<T>` keeps `NeonWriteBatch`. All four already bound *owned* types to the GAT precisely so that dropping it is "a deletion here rather than a redesign" (`crates/happenstance-ladybug/src/projection_store.rs:261-264`). **If an edit to any of them goes beyond restating a signature, the port change is what is suspect, not the skeleton** — report it, do not absorb it. The weaker literal bar, "compile unchanged", is unsatisfiable by this phase's own central decision and must not be restored (`RUNBOOK.md:3942-3948`).

`LiveHandleProjectionStore` (`crates/happenstance-ladybug/src/live_handle.rs:174-219`) is the exception and the interesting one: it binds `type Batch<'a> = GraphWriteHandle<'a>`, a genuinely borrowed live handle, with **real bodies rather than `todo!()`**, and exists to be the compiled counter-example to §4.2's argument. Under `type Batch;` that impl cannot survive as written. **Its disposition — deleted, moved to `experiments/`, or kept with its transcripts and a note that the port no longer admits it — is ADR-0017's, named there, and this story executes what the atom says.** Deleting the only compiled evidence against the decision being made is how a port gets frozen against its own hypothesis (`_decomposition.md:606-627`).

Neon's comment at `:141-152` records a port constraint nobody wrote down: *any* projection-store adapter generic over a type parameter is forced to `'static` by the GAT, whether or not its batch borrows anything — four `error[E0311]`, two pointing into `happenstance-core/src/projection.rs` itself. `type Batch;` makes it vanish. That is evidence **for** this change, and it means the Neon crate is in this story's boundary.

### The three shape-tests are the ones that can go quietly vacuous

Each asserts something about the GAT and each must be restated into a form that still *fails* when the shape is wrong, not deleted and not weakened:

- `crates/happenstance-postgres/src/projection_store.rs:143-178` — `the_batch_does_not_borrow_the_store`. Its own doc records that the obvious spelling (`assert_static::<Batch<'_>>()`) **was written first and certified the shape it was meant to reject**, because `'_` in a turbofish is inferred while `'_` in argument position elides to a fresh universally-quantified lifetime. Under `type Batch;` the argument-position trick has nothing to quantify over; whatever replaces it must be shown to fail against a borrowing batch or be removed with the reason stated.
- `crates/happenstance-ladybug/tests/port_shape.rs:33-78` — the `for<'a> S::Batch<'a>: Send` runner bound, and the `const _` block that instantiates it for both Ladybug impls.
- `crates/happenstance-sqlite/tests/shapes.rs:104-170` — `batch_normalises_to_the_owned_type`, whose `P: ProjectionStore<Batch<'static> = SqliteBatch> + 'static` clause is itself the demonstration that "the GAT costs callers something even when no adapter uses the lifetime".

### What stays untouched, and why saying so matters

- **`ProjectionId::new` stays infallible.** Architecture brief AC-A09 (`_decomposition.md:331-335`); the inconsistency with `EventType`/`Tag` is `.kb/open-questions/projection-id-is-unvalidated.md`'s, and repairing it as a side effect of freezing the port around it is exactly the move the atom exists to prevent.
- **The module's `# Status: provisional` block at `projection.rs:1-11` is not deleted here.** AC-014 disposes of it, in `unstable-projection-gate-and-clause-disposition`. A port whose header stops saying "provisional" before its suite exists is a lie this project is specifically organised to avoid.
- **Nothing `[FROZEN]` is line-edited.** PS-1 and PS-19's known scope gaps are ADR scope carried by `ps-clause-pairing-sweep` and `projection-decision-atoms` (`_decomposition.md:638-661`; CLAUDE.md, "Changing a `[FROZEN]` clause requires a new ADR, not an edit").

### The ordering *is* the check

AC-008 requires ADR-0017, ADR-0018 and ADR-0019 to be **accepted atoms before the port change lands** (`project.md` AC-008; `_storymap.md` merge order, item 2: "Lands strictly after slice 1: AC-008's ordering is itself the check"). At the time of writing `.kb/decisions/` holds 0001 – 0016 plus 0029 and none of 0017 – 0019 — confirm they exist and `redkiln validate --kb` is green **before** editing `projection.rs`, and stop if they do not.

### Persona slice

The reader served here is the **adapter author** (`_decomposition.md:215-219`, the three-readers table). Today they meet a port that no adapter has ever satisfied: `error[E0195]` with nothing to copy from, a `where Self: 'a` obligation propagating into every generic consumer, and a `'static` bound forced on any adapter generic over a transport. This story removes the first two structurally and the third entirely. It does not yet give them anything to copy — that is `memory-projection-store` — which is why this story's own proof is the compiler across five impls and three shape-tests rather than a passing rule.

## Data and migrations

**N/A — no persisted data and no schema this story owns.**

Three things that might look like migrations and are not:

1. **No storage schema changes.** Every body touched here is `todo!()` or, in `LiveHandleProjectionStore`'s case, disposed of by ADR-0017. No checkpoint table, no read-model table and no DDL exists in this workspace to migrate; the checkpoint row's shape stays adapter-owned by design, because `reset` takes the caller's own deletes precisely so the port never learns what a read model is (`spec/SPECIFICATION.md:5165-5170`).
2. **No compatibility shim for the source-level break.** This is a breaking change to a trait with five implementers, and it ships with **no deprecated arm**. Nothing in the workspace is published, so no downstream consumer is pinned — the same reasoning that removed the testkit's old `factory =` spelling outright at phase 3 with no deprecated arm (CLAUDE.md, "The rule that matters"). Every crate that implements this port carries `publish = false` (`crates/happenstance-postgres/Cargo.toml:12`, and the same line in `happenstance-ladybug`, `happenstance-sqlite`, `happenstance-neon`), so not one of the five impls is a semver promise to anybody.
3. **No data-shaped semantic change to `Checkpoint`.** `Option<SequencePosition>` becoming a three-variant enum widens what the port can *report*; it does not reinterpret any stored value, because no adapter stores one yet. `SequencePosition` itself is untouched and stays `NonZeroU64`-backed (`crates/happenstance-core/src/event.rs`), which is what makes "never run" a state the port can report and no method can produce.

## Implementation notes (non-prescriptive)

Not instructions — the decisions already taken elsewhere that an implementer would otherwise have to rediscover, plus the ones deliberately left open.

- **Order the work so the ordering is visible.** ADRs first (they are a dependency, not a step), then `projection.rs` and `lib.rs` in one commit, then the five restatements, then the three shape-tests. That sequence makes AC-009's precondition and AC-008's "signature lines only" claim both readable from the history rather than argued in prose.
- **Do the mechanical part mechanically.** Removing the GAT is a deletion at each impl site, not a redesign, precisely because all four surviving impls already bound *owned* types to it (`crates/happenstance-ladybug/src/projection_store.rs:261-264`). Expect the restatement to be small and boring; if it is not, EC-003 is firing.
- **The three module docs that quote a signature.** `crates/happenstance-sqlite/src/lib.rs:40` (`type Batch<'a> = rusqlite::Transaction<'a>`), `crates/happenstance-neon/src/lib.rs:83-84`, `crates/happenstance-ladybug/src/lib.rs:37,65`. A module doc quoting a signature its crate no longer has is a rustdoc lie no gate step catches — it is neither a broken intra-doc link nor a failing doctest. These are in the PR boundary for that reason alone.
- **`begin` is where the temptation lives.** It is the one item whose asymmetry with `EventStore` will read as an oversight. The brief says it outright: *"Do not 'improve' it back to `async fn begin() -> Result<…>` for symmetry"* (`_decomposition.md:700-704`). AC-004's test exists to make that a compile error rather than a review argument.
- **The foreign-batch stamp is scaffolding here, behaviour later.** This story lands `ForeignBatch` on both enums and the doc that says the check is a run-time integer comparison against a per-store-instance identity. Whether `begin` actually stamps, and the rule that exercises it, is `commit-rollback-and-drop-rules`'. Landing the variant without the mechanism is deliberate: the variant is contract surface, the mechanism is adapter behaviour a rule must convict.
- **Left open on purpose, and owned elsewhere:** how many of §4.11's seventeen adapter rules eventually ship (`_decomposition.md:672-676`, audited by AC-014); one mutant binary or two (`:677-683`); DT-3's capability set (`_design.md`, via `projection-api-design-record`). - **Two standards atoms, not the corpus.** `standards/rust/30-error-taxonomy.md` for the two enums, `standards/rust/70-rustdoc-obligations.md` for the doc obligations. The UX brief names the same pair and says to pull `30-error-taxonomy` *in place of* one of its three, not in addition (`_decomposition.md:221-226`); the router's instruction is one to three at a time.
- **Never assert a literal position.** `CheckpointRegression { current, attempted }` is a shape, not a licence: any later comparison uses positions the store actually assigned.

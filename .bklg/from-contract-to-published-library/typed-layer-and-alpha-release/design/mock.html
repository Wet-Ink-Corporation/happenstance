Substrate ledger — what is real here, and what is not

This repository has no design system, and that is a finding rather than a gap. It is a Rust library: no CSS, no HTML, no font, no package.json and no shared UI package is tracked anywhere in the tree, and design.capture is deliberately absent from .redkiln/config.yaml so the perceptual review is a declared skip. Naming a primitive here would mean inventing one.

So the mock went and got the real substrate instead. Two of the six surfaces render through rustdoc, which is their design system. A throwaway crate carrying exactly the module doc, the item set and the feature gates this design specifies was compiled three times — default, --no-default-features, and --all-features --cfg docsrs on nightly — and the frames below embed that output verbatim, with rustdoc's own stylesheet, its own light-theme custom properties and its own class contracts. Two consequences worth stating plainly:

  • The design is buildable. All three builds now emit zero rustdoc warnings.
  • Getting there changed the design. The first build warned three times: the vocabulary and Features regions linked Cbor, Postcard and run_projection, none of which exist under default features, and commit_with's summary linked two items that vanish under --no-default-features. RS-70-2 was satisfied only after the doc lines were made conditional with cfg_attr. No brief had asked for that, and no textual review would have caught it.

Where no substrate exists at all — a terminal, a panic message, crates.io's markdown — each surface's substrate row says so in its own words, and the styling is namespaced --mock-* or scoped under .md / .term so it can never be mistaken for one.

Caveats a reviewer should hold while looking

  • rustdoc frames carry no JavaScript. The topbar and toolbar are custom elements that rustdoc's main.js populates; with scripts stripped they render empty. Sidebar, item table, doc block, code highlighting, doc_cfg badges and every layout rule are unaffected.
  • Fonts are the system's, not rustdoc's. The 14 @font-face rules were removed so the page fetches nothing; rustdoc's declared fallbacks (serif / sans-serif / monospace) apply. Column counts in the budget table are computed from the text, so they are exact; the apparent width of a line on screen shifts a little with the substituted face.
  • Item pages are not a declared surface and are not drawn. The mock crate's bodies are stubs; only names, summaries, doc text and feature gates are load-bearing, which is exactly what the crate-root page renders.
  • The fence is marked ignore in the mock crate, because the typed layer does not exist yet. rustdoc's “not tested” marker and its ignore class are stripped from the embedded HTML; the highlighting, the <pre class="rust rust-example-rendered"> contract and the layout are rustdoc's own and untouched.
  • Four things this mock exposed and deliberately did not settle: (a) whether region 2 keeps its above-the-fold claim at 81 lines and 107 columns, or the derive lands first (F-01, F-11); (b) whether the Features table has four rows or five — Composition says four, Transience policy says five, and the frames render five (F-05); (c) that anti-pattern 5 is unfixable inside this project, because all 3 over-budget item summaries and all 4 over-budget item names on the crate-root page arrive through pub use happenstance_core::* and are frozen by AC-A02 — the anti-pattern needs rewording or the budget needs a scope (ledger, F-01); (d) whether the transcript's 22-character type column widens or the row loses its alignment when an event type overruns it (F-20).

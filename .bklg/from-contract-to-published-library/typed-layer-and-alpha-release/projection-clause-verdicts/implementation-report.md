# Implementation Report — PS-33, PS-27, PS-30 settled and PS-18 excluded, on the record

**All ten ACs are satisfied. Nothing is blocked and nothing is deferred.**

Four maturity markers stopped being promises to look later. PS-33's falsifier was
evaluated and **fired**: there is no checkpoint pump in `happenstance-core` and there never
was, so the pump collapses upward and ADR-0007 is superseded — by a decision *staged* for
the human-invoked ingest, never hand-written. PS-27 and PS-30 came back as documented
exclusions counted against the runner the slice-mate actually built, each naming its owner
and the artefact that would reopen it. PS-18's exclusion was rewritten from the reason
planning predicted to the reason the tree gives. PS-32, PS-33 and PS-35 left the clause
space with their IDs retained, §1.3's census was re-derived by hand, and the generated
region was regenerated last.

**The verdicts are held to the tree by five executed tests**, not by a reviewer's memory.
`crates/happenstance/tests/projection_clauses.rs` asserts both halves of every count: the
fact about the tree the verdict rests on, and the verdict text in the clause. Grow the
runner a skip policy and the clause saying it has none goes red; revert a marker and the
same test goes red from the other side.

## Defect log entries routed to HS-S0032

Recorded with their clause IDs, **and none of them fixed**. `git status --porcelain --
xtask/src` is empty and CF-36's clause body is unchanged in the diff.

**1. CF-36 names a check that is not implemented.** `[FROZEN]`, at
`spec/SPECIFICATION.md:8611-8622`. Its `Rule:` line reads *"`cargo xtask spec-trace`
(CF-38), cross-referencing each case's level marker (E2E-CASES.md:19-28)"*. The checker
reads no level marker at all: `grep -c "Level" xtask/src/spec_trace.rs` returns **0**. So a
frozen clause cites a cross-reference nothing performs, and the clause it is supposed to
protect — *a clause backed only by integration-level cases MUST NOT name a conformance
rule* — is enforced by review alone. This story relied on that rule to decide where its
tests live, which is how the gap surfaced. **Owner:** `defect-log-and-macros-verdict`
(HS-S0032), BR-01 record. Fixing it means either implementing the cross-reference or
superseding CF-36, and both are decisions rather than patches.

**2. The `†` in §7.2 and a `[DEFERRED]` marker now state the same fact twice, and the
dagger names no owner.** PS-27's row renders `` `skip_and_record_is_atomic` † `` and
PS-30's `` `panicking_apply_rolls_back` † `` — *must be written* — against clause bodies
that now say, in terms, that those rules deliberately do not exist yet and name HS-P0010 as
the owner. The dagger is not wrong, but it is redundant with the marker and carries no
owner, so a reader who trusts the generated table learns less than one who reads the
clause. Related and load-bearing: `spec_trace.rs`'s check 4 short-circuits on
`!has_suite(&c.id)` (`:695-697`), so **no `PS` clause's rule name is resolved at all**
today — a green `spec-trace` is not evidence that a `PS` rule exists. **Owner:** HS-S0032.

**3. A private module can shadow a glob-re-exported one, and nothing in the tree said so.**
Carried forward from HS-S0026, where `mod projection;` in `happenstance` silently shadowed
`happenstance_core::projection` reached through `pub use happenstance_core::*;`. The design's
anti-pattern 14 is written about *type* names; this arrived through a *module* name and
produced only a `hidden_glob_reexports` warning, which `-D warnings` catches in the gate but
which no rule, clause or standards atom anticipates. **Owner:** HS-S0032, as a candidate
addition to `standards/rust`.

## Notes

**PS-18's planned verdict was wrong, and the grep is why we know.** This story's spec
asserts as settled that *"PS-18's subject does not exist — there is no `reset` method and no
`ResetError` anywhere in `crates/happenstance-core/src/projection.rs`"*, and instructs the
implementer to *"re-run at implementation time rather than assumed"*. Re-run, it comes back
the other way: `reset` is at `:497`, `ResetError::Refused` at `:287`, and
`refused_reset_changes_nothing` is a registered projection-suite rule
(`crates/happenstance-testkit/src/projection.rs:1360`, `:1909`) — all landed by HS-P0010
after this spec was written. The exclusion still holds, but for a **different and better
reason**: the mechanism and its instrument both exist, and what is missing is an adapter.
The clause says that rather than the planned sentence, and the count is recorded as
*unavailable* rather than *zero*, which is a distinction the reader can act on.

**PS-33's verdict is branch two, and it could not have been branch one.** Branch one asks
for an independent caller of the core-side checkpoint pump, named by repo path. There is no
pump: `happenstance-core` publishes exactly two free functions in the entire crate,
`collect` (`crates/happenstance-core/src/store.rs:285`) and `read_decision_model` (`:321`).
So the count is not zero over a function that exists — it is unavailable over a function
that never landed, and both readings fire the same falsifier. The superseding decision is
**staged**, at `.kb/_intake/0032-adr-0031-the-runner-collapses-upward.md`, because an
accepted decision atom is immutable and hand-writing one produces the directory layout of
the process without the process. This story does not run `/redkiln:kb-ingest` and touches
no file under `.kb/decisions/`.

**One file outside the declared boundary changed: `standards/rust/01-standard-of-evidence.md`.**
Its Evidence line cited `spec/SPECIFICATION.md:5787 (silently ignores)`, and this story's
insertions pushed that sentence to `:5910`. `cargo xtask lint-constitution` — a REQUIRED
gate step — failed on the drift, and the repair is a one-token line-number update with no
change of meaning. This is the same mechanical consequence two earlier commits on this
branch already carry (`d95c760`, `b77cffb`); it is the cost of mounting an edit into a
document other files cite by line, not scope drift.

**Both PS-27 and PS-30 came back as exclusions, and that was not the assumed outcome.**
`_design.md`'s states table hoped for a skip recorded in the same transaction as the
checkpoint and a rollback on a caught panic. The signed-off *signature* carries no failure
policy, and the runner the slice-mate built has none — so the states table described an
intention and the signature described the tree, and the verdicts were written against the
tree. Neither clause is withdrawn: the Kestrel Motor shred case still needs PS-27, and a
fan-out runner would still owe PS-30 a rollback. Both are deferred with an owner and a
named reopening artefact, which is what makes them decisions rather than patience.

**No third outcome was taken.** Nothing was left `[PROVISIONAL]` with a rewritten falsifier
saying the same thing in different words. Every one of the four moved marker carries a
count that was executed, and the executed count is in this crate's `tests/`, in the affected
gate, running on every story-grain verify.

## One-line PR slice

Delete the last `todo!()` on a SQLite path and `crates/happenstance-sqlite/src/lib.rs:76-80`'s scoped `#![allow(clippy::todo)]` **in one commit**, rewrite the crate's published front page so it stops describing the skeleton it used to be, and take `cargo xtask ci --fast` green end to end — recording, in the same breath, what `--fast` does not run.

## Executive summary

Everything this project promised is, by the time this story starts, already true in the test binaries: `event_store_conformance!` is green against a real file (`sqlite-fixture-and-whole-suite`), the concurrency and model families are green (`concurrency-family-and-contender-count`, `model-family-and-mutant-pass-column`), the reopen rules have a negative control (`reopen-negative-control-and-durability-verdicts`), and the projection store passes a suite it did not write (`projection-store-passes-the-borrowed-suite`). **None of that reaches a reader.** `crates/happenstance-sqlite/src/lib.rs:1-24` still opens with *"# Status: an instrument, not yet an adapter"* and *"Every operation that touches SQL is `todo!()`"*; `:47-65`'s *Open decisions* still lists the append-condition strategy and tag storage ADR-0022 settled; `:76-80`'s scoped `#![allow(clippy::todo)]` — whose own comment says *"Phase 8 removes both the bodies and this line"* — is still there. This PR is where the crate stops being an instrument in the tree as well as in the harness.

The delta on top of the five predecessors is three things, and only one of them has a machine behind it.

**One.** The allow is the *only* thing standing between a `todo!()` on a SQLite path and a denied lint (`Cargo.toml:128`, `todo = "deny"`; no `xtask` lint greps this crate — `xtask/src/lints.rs` reads the testkit's `src/`, manifests, `CHANGELOG.md` and rule files, and nothing else). So deleting the allow while a body survives fails clippy, and deleting the last body while the allow survives leaves a permanent marker asserting the opposite of what is true and nothing anywhere notices. DR-01's *"in the same change"* is therefore a construction, not a preference, and `require_commit_provenance: true` (`.redkiln/config.yaml:73`) is what makes the one-commit claim checkable.

**Two, and it is the residual nobody's spec claimed.** `head` and `contains_event_id` are `todo!()` today (`crates/happenstance-sqlite/src/event_store.rs:234`, `:244`) and every sibling excludes them by name — `append-atomicity-and-store-limits` says *"Do not implement `read`, `head` or `contains_event_id`"* (`:281`), `sqlite-fixture-and-whole-suite` excludes *"any SQL body"* (`:243`). `suite.rs` calls them 21 times, so in practice the fixture slice cannot be green without them; if they none the less arrive here still marked, they are **this** story's, because "the last `todo!()` on a SQLite path" is this story's name. That is why `crates/happenstance-sqlite/src/**` is in the PR boundary and is the entry a reviewer should challenge.

**Three, and it is the half that survives every possible green run.** The module documentation. `cargo xtask ci --fast` builds the docs with `RUSTDOCFLAGS=-D warnings` (`xtask/src/main.rs:290-303`) and checks that their intra-doc links resolve; it does not read them for truth, and no lint in this repository does. So the crate can be a conformant, publishable adapter whose front page tells docs.rs it is a skeleton — and whose next reader implements the schema sketch that holds a join under the write lock. The control is a named review item and a ledger row, not a machine, and this spec says so rather than pretending otherwise.

## Context pack

Read this section and you can start. Everything below the anchors table is retrieval, not prerequisite.

**1. The two deletions are one change, and the reason is mechanical.** `clippy::todo` is `deny` workspace-wide (`Cargo.toml:118-128`), and the workspace comment records why the *scoped* allow is the visible artefact: the lint was once `allow` workspace-wide *"for stub crates that were intentionally unimplemented… the allow protected nothing and would have silently accepted the first real one."* The crate's own allow names the phase that removes it (`crates/happenstance-sqlite/src/lib.rs:76-80`). **Decision: the last SQL body and that attribute leave in one commit.** Splitting them across two commits leaves both green in isolation and satisfies DR-01 by coincidence — which is exactly the shape in which the second commit does not happen (discover.md, third mutant). The check is `require_commit_provenance: true` plus a diff read, never a test.

**2. `#![allow]` is silent in both directions, and that is the trap.** RS-90-3 (`standards/rust/90-skeletons-and-todo.md:181`) is explicit: `#[expect]` fails the build on the day the lint stops firing; `#[allow]` says nothing when it stops suppressing anything. This crate carries `#![allow]`, so **nothing fails if you fix every body and leave the attribute** — no clippy warning, no rustc warning, no gate step. AC-001's verification is therefore a diff read plus `rg`, and the story's own honesty about that is a deliverable rather than a caveat. Do **not** "improve" this by converting the attribute to `#![expect(clippy::todo)]`: an expectation with nothing left to expect is itself an unfulfilled-expectation error, and the correct end state is no attribute at all.

**3. The grep is a convenience the obvious mutant defeats in one character.** Replace `todo!()` with `unimplemented!()` and: `clippy::todo` is satisfied, `clippy::unimplemented` is not in the workspace lint table at all (`Cargo.toml:108-132` denies `unwrap_used` and `todo` and says nothing about `unimplemented`), none of the five file-reading lints reads this crate, `rg 'todo!'` returns nothing, and `cargo xtask ci --fast` is green. The same mutant wears `unreachable!()`, `panic!("not implemented")` and a fabricated `Err(SqliteEventStoreError::…)`. **Decision: AC-014's evidence is the green suites plus the deleted allow — never the grep alone.** That is precisely why this story `depends_on` three stories that each take a suite green: a body replaced by `unimplemented!()` fails whichever rule reaches it, loudly.

**4. `head` and `contains_event_id` are the residual, and this story is their fallback owner.** Both are `todo!()` at `crates/happenstance-sqlite/src/event_store.rs:234` and `:244`; both are excluded by name from `append-atomicity-and-store-limits` (`:281`) and from `sqlite-fixture-and-whole-suite` (`:243`); `suite.rs` calls them 21 times, so the fixture slice is red without them. **Decision: if either arrives here still marked, implement it here** — under the constraints the skeleton's own comments already state, which are not this story's to re-decide: `head` is `SELECT max(position)` asked of the database *every time* and never a cached field an `append` updates (ES-30's stale head; ADR-0013's global visibility invariant, `.kb/decisions/0013-position-assignment-and-visibility.md`), `NULL` mapping to `None` rather than to an error; `contains_event_id` is a lookup on the `UNIQUE(origin_store, origin_position)` pair that `schema-migration-and-identity` created. If both arrive implemented, this story's code change is the attribute and the docs, and the ledger says so.

**5. The module doc is published documentation, and it is a marker in prose.** Four false statements ship on docs.rs today: the *"Status: an instrument, not yet an adapter"* banner (`lib.rs:3`), *"Every operation that touches SQL is `todo!()`"* (`lib.rs:5-6`), *"It is `publish = false` until it passes … the conformance suite"* (`lib.rs:22-24`) — it has now passed, and publication is still someone else's decision, which is a different sentence — and the *Open decisions* section (`lib.rs:47-65`) listing what ADR-0022 settled. Two more sit one level down: `# Status: bodies unimplemented, types real` at `event_store.rs:3` and `projection_store.rs:3`, plus `crates/happenstance-sqlite/tests/shapes.rs:3` (*"every body is `todo!()` in the crate under test"*). **Decision: this story owns the status-and-openness prose crate-wide, including its test targets.** The *schema sketch* is not this story's to rewrite — `schema-migration-and-identity` owns it (`:359`, *the `# Intended schema` block is rewritten to what `migrate` creates*) — but this story **verifies it happened** rather than assuming it, because a doc correction is exactly the kind of item a green run absorbs (discover.md, question 1).

**6. Rewriting those docs moves lines the specification cites, and spec-trace is a `--fast` gate step.** `cargo xtask spec-trace` checks that every `file:line` citation in `spec/SPECIFICATION.md` resolves *and* that the derived subject sits within `ANCHOR_SLACK = 12` lines of the cited line (`xtask/src/spec_trace.rs:291-368`, `:391`). `SPECIFICATION.md` cites this crate at `event_store.rs:47-53`, `:151-193`, `:195`, `:202` and `projection_store.rs:208`, `:215-224`, `:235-260`, among others. **Decision: `spec/SPECIFICATION.md` is in this PR's boundary for citation line-number repair only** — repairing what this PR's own edits moved is part of "the gate is green", not scope drift. Clause text, maturity markers and §7.3–§7.6 judgement are **not** touched: markers are `reopen-negative-control-and-durability-verdicts`', and the clause-range audit is `spec-and-code-reconciliation`'s (AC-016), which is blocked on this story precisely so it reads the code in its final state.

**7. `publish = false` stays, and the runbook checkbox that says otherwise is stale.** `RUNBOOK.md:4230` reads *"`publish = false` removed"*; architecture brief AC-A05, project AC-015 and the initiative decomposition all say the opposite, and they are the current authority (discover.md, question 4). **Decision: this story touches neither `publish = false` in `crates/happenstance-sqlite/Cargo.toml` nor `PUBLISHABLE` in `xtask/src/package.rs:86`, nor the crate's `description`** — the description, README and licence files are `crates-io-name-and-packaging-facts`' (AC-015), which is blocked on this story because a README cannot state the adapter's real durability settings until they exist.

**8. `--fast` is a real bar and a partial one, and the ledger must say which.** `cargo xtask ci --fast` runs `REQUIRED` and skips `OPTIONAL` (`xtask/src/main.rs:105`, `:535`, `:853`): it keeps fmt, clippy `-D warnings`, the whole-workspace `cargo test --all-features`, the proof-artefact step, **all four wasm32 steps**, docs, spec-trace, the five file-reading lints, the constitution checks, the no-default-features doc build and `package-check`; it drops the two feature powersets, `cargo deny` and the nightly `--cfg docsrs` build. So DR-08's re-check of the `bench` feature's target gating happens here through the wasm32 steps — but the **wasm32 feature powerset does not run**, which is the gap `benchmark-harness` was written against. DR-08 is *re-checked* here, never *discharged* here (`_storymap.md`, *Coverage*). A green `--fast` presented as a green gate is the misreading to avoid; `cargo xtask ci` whole is `closeout-and-durable-audience`'s (`.redkiln/config.yaml:60`).

**9. The persona-journey slice.** The user is the same one the story map names throughout — *the adapter author who is also the library's consumer* — and this story is the only one in the project whose increment is **legibility** rather than capability. Everything else made the store work; this makes the store *say* that it works, to the two audiences that cannot run the suite: a reader on docs.rs, and the next implementer who opens `lib.rs` looking for what is still open. BR-03's *"nothing counts toward an outcome until it has passed the suite"* has a mirror image, and this is it: a crate that has passed the suite and still describes itself as a skeleton has not delivered the outcome to anyone who did not run the tests.

## Data and migrations

**N/A — no schema change, no migration, no persisted-data shape decided here.** Migration 1 and everything in it — the `event` / `event_tag` / `tag_cardinality` tables, the `EventId` origin pair, `recorded_at`, the persisted `StoreId`, WAL and the `synchronous` and busy-timeout settings — is `schema-migration-and-identity`'s, settled under ADR-0022 (`_storymap.md`, `durable-event-store` slice). This story runs *against* that schema and documents it; adding, renaming or indexing anything to make a body or a doc line work would be re-deciding a settled story from inside this one, and is a finding to escalate.

Three data-adjacent facts an implementer needs anyway, none of which is a migration:

- **`head` reads, it does not remember.** If `head` lands here, it is `SELECT max(position) FROM event` asked of the database on every call, on a blocking thread like every other statement. It must never become a field this store caches and `append` updates: one file backs several handles, so a second connection's commit makes a cached head stale, and that is the exact defect ES-30 exists to reject (`crates/happenstance-sqlite/src/event_store.rs:226-235`; `.kb/decisions/0013-position-assignment-and-visibility.md`). `NULL` on an empty table is the `None` arm, not an error.
- **`contains_event_id` reads the identity pair the schema already has.** `origin_store` and `origin_position`, `UNIQUE` together — the same index that serves ingest's duplicate guard. The skeleton's own comment says those columns are absent from the *sketch*; by the time this story runs they exist in the migration, which is one more reason the sketch verification (AC-003) is a real check rather than a formality.
- **Positions may gap, and nothing this story writes may assume otherwise.** `AUTOINCREMENT` guarantees positions are never reused after a delete and the specification permits gaps. No assertion, doc example or rewritten paragraph added here may state or imply `+1` (`CLAUDE.md`, *never assert on literal position values*).

If it is already empty, this story's code change is the attribute plus the prose, and the ledger for AC-002 should say so explicitly, citing the predecessor that closed each path. If `head` or `contains_event_id` survive, they are yours (context pack 4) — their own comments at `event_store.rs:226-245` already state the constraints, which are not this story's to re-decide.

**Rewrite the documentation last, then repair `spec-trace` once.** Every doc edit shifts line numbers beneath it, and `spec/SPECIFICATION.md` cites this crate at several of them. Editing prose, repairing citations, editing prose again and repairing citations again is how a citation gets repaired to a line that a later hunk moves. Land the bodies, land the attribute deletion, then do all of the prose in one pass and run `cargo xtask spec-trace` once against a settled file.

**Do not convert the attribute.** `#![expect(clippy::todo)]` is the usual improvement over `#![allow]` (RS-90-3, `standards/rust/90-skeletons-and-todo.md:181`) and it is wrong here: an expectation with nothing left to expect is itself an unfulfilled-expectation error. The end state is no attribute.

**Consider earning a machine for the front page.** The single largest unenforced claim in this story is that the module documentation is true. One cheap strengthening, entirely optional and explicitly not an acceptance criterion: a doctest on the crate root that opens a store against a temporary file and appends, so that the front page's central claim — this is an adapter, and here is it working — is *compiled* by `cargo test --workspace --all-features`, which `--fast` runs. If it costs a new dev-dependency or a feature, drop the idea; the cost is not worth a new manifest entry in this PR.

**The one-commit discipline is a staging discipline.** Implement and verify freely across as many local commits as you like, then squash the body change and the attribute deletion together before the checkpoint. What must be true of the *recorded* commit is that both halves are in it.

**When the schema sketch check fails, the story stops.** EC-003 is the one condition where the correct action is to raise and block rather than to fix, and it is worth saying twice because the fix is a two-line edit anyone would make reflexively.

## Risks and coupling (PR-scoped)

- **The documentation is load-bearing and unenforced — and this is the second place in the project where that is true.** No lint reads prose for truth. The whole of **AC-003** rests on a named review item, and the failure mode is silent and durable: the crate ships correct and describes itself wrongly, and the next implementer builds from the description. *Mitigation:* AC-003 is a ledger row with a review obligation attached, the `rg` sweep covers the four known phrases, and the schema-sketch check is object-by-object rather than impressionistic. *Residual:* a paragraph that is subtly stale rather than textually matching a known phrase passes everything. Accepted, and named in the ledger.
- **The two-commit split satisfies DR-01 by coincidence.** Both halves are green in isolation; the story closes with both present; the requirement that the allow cannot outlive the bodies was never *constructed*. *Mitigation:* AC-001's verification is provenance plus a diff read, and `require_commit_provenance: true` makes it re-checkable after the fact. *Coupling:* none outward — this is a discipline risk, not a code one.
- **`head` and `contains_event_id` are a residual with three possible owners.** Every sibling excludes them by name while `suite.rs` calls them 21 times, so in practice the fixture slice cannot be green without them — but "in practice" is not a plan. *Mitigation:* this story is their named fallback owner and `crates/happenstance-sqlite/src/**` is in the PR boundary for exactly that reason. *Risk if it fires:* this story's diff is much larger than a marker-removal PR should be, and the reviewer should read it as an implementation PR.
- **The doc rewrite and `spec-trace` are coupled through line numbers, in both directions.** Repairing citations can drift them; drifting them fails a `REQUIRED` step. *Mitigation:* rewrite once, repair once, as above. *Coupling outward:* `spec-and-code-reconciliation` (AC-016) reads this crate in its final state and is blocked on this story precisely so it does not have to read a moving target.
- **A green `--fast` will be read as a green gate.** It is the most likely misreading of this story's own success, by the next reader and by a closeout audit. *Mitigation:* AC-005 makes the "what did not run" list part of the criterion rather than a footnote. *Coupling:* `closeout-and-durable-audience` owns the whole gate and inherits the assumption that `--fast` was green here.
- **A hang, not a failure, is the plausible late surprise.** The last real body makes the concurrency family exercise the busy timeout for the first time in this crate's life at full strength. *Mitigation:* EC-006 — report, never paper over. *Coupling:* the finding lands on ADR-0022's busy-timeout paragraph, not on this story's code.
- **Scope leak toward publication is one line away.** `publish = false` sits in the manifest this PR does not otherwise open, and `RUNBOOK.md:4230` actively invites the edit. *Mitigation:* AC-006 is a criterion rather than an "out of scope" bullet, so leaking is a ledger failure rather than a review opinion.

## Clarifications resolved during spec

1. **The six AC ids are exactly the front half's six, unchanged.** AC-001 – AC-006 as enumerated above; none added, none dropped. The ledger matches them one for one.
2. **AC-014's three literal clauses are AC-001, AC-002 and AC-005; the other three criteria are its unstated preconditions.** A crate satisfying the literal reading can still lie on its front page (AC-003), break the specification's citations (AC-004) and publish itself (AC-006). Splitting them out is what makes each separately falsifiable rather than folded into a criterion whose evidence is a single green command.
3. **AC-002's evidence is execution, never the grep.** The testing brief's AC-014 row proposes `rg` over `crates/happenstance-sqlite/src` (`_decomposition.md:640`), and it is kept — as a *convenience*. The `unimplemented!()` mutant defeats it in one character while `clippy::todo`, `-D warnings` and all five file-reading lints stay green (`discover.md:87-104`). The criterion therefore requires green rule names from the suites the three predecessor stories mounted.
4. **AC-003 is honest about having no machine, and says so in the criterion rather than in a footnote.** `cargo xtask ci --fast` builds documentation and checks intra-doc links; nothing in this repository reads documentation for truth. Writing the criterion as though the docs step verified it would be the exact failure the story exists to prevent, one level up.
5. **The `CLAUDE.md:33` repository-map row is folded into AC-003 rather than given its own criterion.** It is the same defect in a different file — an in-tree status marker contradicting the front page — and splitting it would produce a criterion whose whole content is one table row.

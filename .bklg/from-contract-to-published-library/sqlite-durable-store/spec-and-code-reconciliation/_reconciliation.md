## Clause-by-clause verdicts (bullet 1 of the criterion)

Every clause in set A, plus every clause that **names this crate anywhere in its
own text — its prose, its `Rejects:`, or its maturity marker — by path or by
name.** Verdict is one of **unchanged**, **repaired** (prose or citation
corrected, the set of implementations the clause admits identical) or **gap**
(escalated, nothing normative changed). No row reads "looks fine".

**The inclusion rule was widened after it let one through.** Its first spelling
was "every clause whose *prose* cites `crates/happenstance-sqlite`" — a
path-shaped test, run with a path-shaped search. CF-40 names the adapter as *"the
rusqlite adapter at phase 8"* inside its `[PROVISIONAL]` marker and cites no path
at all, so it matched nothing, and a clause already sitting in the
symmetric-difference table above was dispositioned on **clause ownership** without
its marker text ever being read. The rule now reads on the identity rather than on
the spelling, and the marker is named explicitly because that is the field the
narrow rule could not see: `happenstance-sqlite`, `crates/happenstance-sqlite/…`,
"the rusqlite adapter" and "phase 8" are all in scope.

The discriminator is `.kb/playbooks/repairing-a-frozen-clause-without-amending-it.md`'s,
applied rather than improvised: *a correction to a FROZEN clause is a repair if
the set of implementations the clause admits is unchanged, and otherwise it is a
gap, which is an ADR's.*

### The routed item, settled

`reopen-negative-control-and-durability-verdicts` moved four §6.5 statements into
agreement and **routed one to this story rather than moving it in passing**: the
handle-multiplicity row still read *"no connection has ever been opened twice"*
while `SqliteFixture::connect` had already falsified it.

**Verdict: the axis has an adapter instrument at its far end, and the row is
repaired to say so.** The far end this table names is *"two or more handles onto
one backing store, concurrent"*. `SqliteFixture::connect` opens another
`rusqlite::Connection` through `SqliteEventStore::open`, configures it and runs
migration 1 (`crates/happenstance-sqlite/tests/support/mod.rs:208`) — not a
refcount bump — and `connect_many` opens up to 64 of them for the concurrency
family (`crates/happenstance-testkit/src/concurrency.rs:1015`), which is green.

**The narrower reading was considered and rejected with its reason**: that only a
*pool-backed* adapter should count. It renames the far end after the fact.
Pooling is a property of how handles are acquired, not of how many exist onto one
store, so it is recorded as **what is still missing** — alongside cross-*process*
handles — rather than as what the row always meant. CF-16 and CF-19 are `[FROZEN]`
and are **unchanged**: this is an edit to §6.5's evidence, not to either clause.

## One file outside the PR boundary, and the reason

`standards/rust/01-standard-of-evidence.md:128` cites
`spec/SPECIFICATION.md:5926 (silently ignores)`, and this pass's insertions moved
that sentence to `:5984`. `cargo xtask lints` — a `REQUIRED` gate step and half of
the `reachability_static` command — went red on it:

```
standards/rust/01-standard-of-evidence.md:128 — `spec/SPECIFICATION.md:5926` no
longer has `silently ignores` within 10 lines; the citation points at the wrong
place
```

**One digit changed: `5926` → `5984`.** No rule text, no evidence claim, no atom
body. It is the same class of repair the slice's first story's AC-004 names —
repairing what this PR's own edits moved is part of "the gate is green", not scope
drift — and the alternative was to leave a `REQUIRED` step red through an edit
this pass caused. The constitution's own citation lint uses a ten-line window
(`xtask/src/lint_constitution.rs:111`), narrower than `spec-trace`'s twelve, which
is why it caught a shift `spec-trace` tolerated.

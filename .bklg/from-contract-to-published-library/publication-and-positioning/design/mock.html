Substrate: there is no design-system primitive layer, and none was invented

Verified in this worktree: find . -name package.json → 0 results; find . -name '*.css' → 0 results; no token file, no theme file, no component package. That is correct for a Rust library workspace — crates.io, docs.rs and GitHub own the theme and none of them honours anything this repository writes.

The primitive set composed from here is therefore the one _design.md names: the rendered-Markdown block vocabulary (H1, blockquote, list, fenced code, table, link) plus rustdoc's own doc(cfg) pill. Where a host emits a stable class contract it is reproduced faithfully — rustdoc's .rustdoc / .sidebar / .main-content / .docblock / .stab.portability / .item-table, and github-markdown-css's .markdown-body. crates.io's DOM classes are build-hashed and unstable, so nothing here claims to mirror them; what is mirrored is its type scale and layout geometry.

All host chrome below is a hand-built facsimile, dimensioned to _design.md ## Density budget (1440×900 → 500 px ≈ 21 lines of README above the fold; 1024×768 → 340 px ≈ 14 lines). It is not a repo primitive and must never be copied into the repo — AP-7 forbids raw HTML or CSS on a published surface. Measuring the live site is AC-007's rendered-page preflight, the instrument this stage does not have (design.capture undeclared; xtask/src/package.rs:4-18 says why nothing automated stands in).

Annotations are not copy. Anything in this rust-orange — the R1…R12 region tags, the fold rule at the bottom edge of a clipped frame, the dashed counter-example strips — is a mock annotation. Toggle the region tags off in the bar above to read a frame as a reader would.

What this mock is asking the approver to decide

  • The 14-line first screen is exact, not approximate. On every first-screen-1024x768 frame the fold rule lands immediately under the third bullet of the triad. Identity 3 + blank 1 + callout 3 + blank 1 + triad 6 = 14. Nothing else fits; the frames show what falls off if anything is added.
  • Badges sit below the maturity census on the packaged surfaces (R5 under R4) and stay at the top on GitHub. Compare the images-blocked frames: on crates.io the region collapses to nothing and costs the reader nothing, which is the argument for the demotion.
  • The 8-row status table is on GitHub only. No crates.io frame contains it. Its overflow and long-label behaviour is shown on the GitHub frames at 1024×768, where the Role cell wraps and the Status cell — glyph and words, never glyph alone — does not.
  • docs.rs shows gated items with their gate. The all-features frames carry rustdoc's real .stab.portability pill; the dashed strip beside it is the AP-8 counter-example — what the same item looks like built without --cfg docsrs (no gate) or without all-features (absent entirely).
  • The docs-build-failed frames are the reason the crates.io README is self-sufficient. No claim on any crates.io frame depends on a docs.rs page rendering.

One finding this mock produced, for the approver rather than for the implementer

The 14-line budget has no slack once headings are charged at their true cost. _design.md ## Density budget models a rendered line as 24 px and allocates identity 3 + blank 1 + callout 3 + blank 1 + triad 6 = 14. Drawn at the real block metrics a Markdown renderer uses — margin-bottom: 16px on every block, an H1 at 35 px, an H2 at 26 px plus its rule and its 24 px top margin — the same five regions measure ≈343 px against a 340 px budget. It fits, but only after the callouts were tightened from three rendered lines to two and each triad bullet to one line, which is what the frames above show.

What the approver is being asked to accept: either the budget's line model gains a heading surcharge (an H1 costs ~2.1 lines, an H2 ~2.8 including margins), or the first screen is understood to be full at 0.2.0 — any sixth region, any callout that grows back to three lines, and the triad's third bullet crosses the fold and AP-1 fails. The demotion order in ## Density budget already names what yields; this finding says it will be needed sooner than the arithmetic implies.

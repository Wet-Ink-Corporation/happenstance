## One-line PR slice

Read the *rendered* crates.io and docs.rs pages for all three crates against the accessibility floor — one H1, no skipped levels, header rows, languaged fences, meaningful link text, alt text, no raw HTML/CSS/JS, no meaning in colour or glyph alone — plus licence, description and README as they read rather than as `cargo package --list` says they are contained, and commit the result as a dated check before the irreversible act.

## Executive summary

This PR lands **the read, the frames and the gate line** — not one line of published copy.

The three stories this one blocks on wrote the surface: `landing-copy-and-status-truth` put DT-1's lead claim on the first screen and corrected the four stale strings, `compliance-claim-and-gaps-promise` landed the claim-with-evidence block and DT-4's positions-and-gaps promise, and `guarantees-and-docs-rs-presentation` filled the Guarantees slot and added the missing `[package.metadata.docs.rs]` block. Every one of them was verified by reading a *source file*. This PR is the first and only time anyone looks at what those files **render as**.

The delta, concretely:

1. A dated, committed record at `.bklg/.../rendered-page-preflight/_preflight.md` carrying a per-surface, per-item verdict for all seven surfaces at both viewports, and a single `GO` / `BLOCK` line at the top.
2. Fourteen frames (seven surfaces × two viewports) dropped at the exact paths `_design.md`:755-764 declares, so the perceptual design review compares the built surface against the mock a human signed off rather than against a description of it.
3. Two edits to `RUNBOOK.md`'s phase-12 section — one **Work** line and one **Exit criterion** — which is what turns the record from an artefact into a precondition of `publish-0-2-0`.

What makes this a story rather than a checklist item is the thing `xtask/src/package.rs`:4-18 says in its own module doc: *"the metadata is what crates.io renders, so the omission is invisible until someone unpacks the tarball."* `package-check` already proves the three files are inside each `.crate`. Nothing in this repository has ever proved they read correctly, and after `publish-0-2-0` nothing can — a yank removes a version from the resolver and leaves the page exactly as it was (`standards/rust/51-features-and-no-std.md`:226-231).

## Context pack

Read this section before opening anything. It is the whole set of decisions this story must honor; the depth behind each one is a signposted anchor in the second half of this spec.

**1. "Rendered" means rendered from the bytes that will ship — and the registry URLs do not resolve yet.** `discover.md`:33 left the exact tooling to this spec. It is pinned here, and it differs per surface family because the fidelity available differs per surface family:

- **crates.io (×3).** Read the README **extracted from the `.crate`**, never `crates/<name>/README.md` in the working tree. `cargo package -p <crate> --allow-dirty --locked` produces the artifact; the read is performed on its contents. This is not pedantry: `include_str!` cannot reach outside a package (`README.md`:131-137), the root README is a different document with different links, and the whole failure class `package.rs` was written against is a file that is fine in the tree and absent from the tarball. crates.io's own Markdown pipeline is not in this workspace and is not reproduced — see decision 6 for what that costs and how it is bounded.
- **docs.rs (×3).** This one is **the real renderer**: `cargo +nightly doc --locked -p <crate> --all-features --no-deps` with `RUSTDOCFLAGS="--cfg docsrs -D warnings"` is byte-for-byte the configuration docs.rs runs given `[package.metadata.docs.rs]`, and it is already a step in the gate (`xtask/src/main.rs`:621-636). The output under `target/doc/<crate>/index.html` is opened in a browser, at both viewports, in both themes — rustdoc ships its own theme switcher, which is what makes `_design.md`'s Theme row (`:630`) falsifiable rather than merely asserted.
- **GitHub landing (×1).** GitHub's own rendering of `README.md` on this branch, before merge.

**2. Capture is manual, and that is a decision, not a gap.** `design.capture` is undeclared in `.redkiln/config.yaml` — there is no app and no route — so the perceptual review is a *skip* rather than a silent pass, and `_design.md`:39-45 names this story as the instrument that replaces it: *"a human reads the **rendered** page before the irreversible act."* `_design.md`:766-768 goes further and says capture *"stays manual at AC-007."* **Do not build a renderer, a capture harness, or a Markdown-diff tool.** The testing brief forecloses it in terms (`_decomposition.md`:548-553): automating this *"would be inventing a new mechanism where the grounding explicitly says to point at the existing one and stop."* The one thing that is checked mechanically — every link and every held anchor — is AC-UX-011 and belongs to `landing-copy-and-status-truth` (`_storymap.md`:67, its own row); this story **consumes** that check's result and does not re-implement it.

**3. The nightly docs step is behind a probe, so "the gate was green" does not mean the docs.rs configuration was ever built.** `xtask/src/main.rs`:602-636 makes the `--cfg docsrs` step optional-with-probe on purpose (a contributor should not need a second toolchain), and `--fast` — this project's own integration gate (`.redkiln/config.yaml`:50-56) — drops it entirely. `standards/rust/70-rustdoc-obligations.md`:230-234 names the resulting failure by name: *"A published version whose docs.rs build fails while every local gate was green, because the nightly step is behind a probe and skips on a machine with one toolchain."* The preflight therefore records that the nightly build **ran**, on this machine, at this commit — not that the gate was green. Two further traps sit in the same step: it names `-p happenstance-core -p happenstance-testkit` and **not** `-p happenstance` (`:627-630`), so the crate a `cargo add` evaluator meets may never have been built under `docsrs` by anything; and the step's `-D warnings` reaches rustdoc only through `RUSTDOCFLAGS` (`:82-88`).

**4. A finding is a stop, not a fix.** This story edits no copy, no manifest and no `crates/**` file. That is the same posture the project takes one level up — DR-15 makes a wrong `[FROZEN]` clause a blocker and a re-plan rather than an edit (`project.md`:217-219) — applied to prose. A failed floor item or a tripped anti-pattern is written into the record with the **owning story named**, and the fix lands as a follow-up commit by that owner. Because the preflight read, the gate run and the publish are *"therefore one context"* (`_storymap.md`:91-96), that follow-up is inside this slice; it is not a new story and it is not a silent edit made here. Where a finding cannot be absorbed by a copy owner — a wrong `[FROZEN]` clause, an API shape — `_storymap.md`:186-191 is explicit that it *"becomes a new decision atom and a re-plan, not an edit inside this project."* The routing table is in *Behavior and interfaces*.

**5. Seven surfaces and two viewports, and the narrow one is the design case.** `_design.md`:104-169 declares seven surfaces, not three. The binding viewport is **1024×768**, where crates.io stacks its metadata block above the README and leaves ≈340 px ≈ 14 rendered lines above the fold (`:452`, `:456-458`, `:628`). The sign-off accepted a measured **≈343 px against a 340 px budget** and declared the first screen **full at 0.2.0** (`:744-752`, `:777-783`): any sixth region, any callout regrown to three rendered lines, or the triad's third bullet crossing the fold makes **AP-1** fail. This preflight is where that budget meets the actual render instead of the mock, so the measurement is taken in **pixels at a stated zoom**, and the 24 px-per-line model is used only to explain a number, never to produce one.

**6. State what the instrument could not see.** The preflight approximates crates.io's renderer and cannot approximate its sanitizer. That limit is written into the record with its reason, because `.kb/decisions/0010-the-suite-must-prove-itself.md` is this repository's standing rule that *a skip is reported, never silent* — the same discipline the testkit applies to a declined capability, applied to a check. Two mitigations bound the exposure and both are already true of the tree: the packaged surfaces use only the CommonMark/GFM constructs already standing in `crates/*/README.md` (heading, blockquote, list, table, fenced code, link, image), and AP-7 forbids raw HTML, inline `style`, JavaScript, custom colour and animated media outright (`_design.md`:658-659). What is left over is stated, not covered up.

**7. The persona slice this realizes.** Persona 4, the evaluator — one-shot, time-boxed, *"whatever they spend reading a registry page and a README once"* (`_discovery/distillation/personas-and-journeys.md`:333-338), and unable to run the suite (`:262-266`). U8 is the intent: *"tell me honestly where it is not finished, before I find out"* (`_decomposition.md`:89). There is no second pass to correct a first impression, and the version number that carries the first impression cannot be edited. That asymmetry — not thoroughness for its own sake — is why the read is exhaustive and why it happens before the act.

**8. What this story is not permitted to settle.** DT-1, DT-4, DT-5 and DT-6 are resolved in `_design.md` and are not reopened by a reader who disagrees with a rendered result. PS-3 belongs to `projection-port-ship-shape`. The crate set is `crate-set-decision`'s and is exactly three (`_decomposition.md`, deployment brief, `:576-580`). If the read produces an argument for changing any of them, it goes in the record as a finding and becomes a re-plan.

## Integration contract

**Archetype** — `capability`. A user-observable slice: the observable outcome is that the evaluator meets a page that reads correctly, and the mechanism that produces it is a dated read that gates the publish.

**Slice / milestone** — `the-release-event`. Slice-mates, implemented in one context and mounted as one surface: `rendered-page-preflight` (this story) → `publish-0-2-0` → `stranger-install-smoke`. The slice is cut this way because reversibility has to be bought *before* the act (`_storymap.md`:91-96), and the order inside it is protected against re-planning (`_storymap.md`:179-184).

**Mount point** — **`RUNBOOK.md`, § "Phase 12 — Publish `0.2.0`"**: the **Work** checklist at `:4466-4479` and the **Exit criteria** at `:4489-4505`.

That is the composition root of the release event in this repository. `CLAUDE.md` calls `RUNBOOK.md` *"the plan of record, and how far it has got"*, phase 12's checklist is the list `publish-0-2-0` walks, and a preflight that is not on it is a check nobody is obliged to run before the one act that cannot be undone. Concretely, this story adds one ordered **Work** line — the preflight read, dated, recorded, sitting **above** the *"Publish in dependency order"* line at `:4469-4471` — and one **Exit criterion** naming the record's path. Nothing else in phase 12 is touched: the stale four-crate goal line (`:4450-4451`) belongs to `crate-set-decision` and `publish-0-2-0`, and the stale `#the-46-provisional-clauses` anchor (`:4495`) belongs to `falsifier-ledger-repair` and `deferred-clause-reread`. Leaving them is deliberate, and the record says so rather than letting a reader think they were missed.

## Implementation notes (non-prescriptive)

A workable order, offered rather than imposed:

1. **Write the empty grids first, then read.** Eight floor items × seven surfaces, fifteen anti-patterns × seven surfaces, the region measurement table, the licence/description/README block per crate. A grid authored before the reading makes a missed cell visible; a grid authored after it makes a missed cell invisible, which is exactly what EC-009 is about.
2. **Produce the artifacts before opening anything.** `cargo package -p happenstance -p happenstance-core -p happenstance-testkit --allow-dirty --locked` writes `.crate` files under `target/package/`; they are gzipped tarballs, and the `README.md` inside each is the file to open. Note each version into the record as you go, not from memory afterwards.
3. **Run the docs build once, for all three crates, with the flags spelled out.** `RUSTDOCFLAGS` is the only channel by which `-D warnings` reaches rustdoc (`xtask/src/main.rs`:82-88); passing it as a `cargo doc` flag silently does something else. `target/doc/<crate>/index.html` opens directly in a browser, and rustdoc's own theme switcher covers the light/dark states without any tooling.
4. **For the crates.io surfaces, render the packaged README through the same geometry the mock was dimensioned to** — content column ≈ 800 px at 1440×900, metadata stacked above the README at 1024×768 with ≈ 340 px above the fold (`_design.md`:446-458). `design/mock.html` is self-contained and already draws the fold rule where the budget says it falls; using it as the comparand is the point of its existing.
5. **Measure in pixels with the browser's own tools, at 100% zoom, and write the zoom down.** Region heights come from the rendered box, not from counting lines and multiplying by 24 — the sign-off's own finding was that heading margins break that arithmetic (an H1 ≈ 2.1 lines, an H2 ≈ 2.8 with its rule and margins).
6. **Block images with the browser's own setting** rather than by deleting badge Markdown. The point is what the evaluator sees when a CDN is unreachable, and a deleted badge is not the same experiment.
7. **Capture the fourteen frames as you go**, named exactly `<surface>@<viewport>.png` per `_design.md`:755-764, so the design review's comparand and the reader's evidence are the same files.

## Clarifications resolved during spec

1. **The AC set is exactly the ten the front half enumerated** — AC-001 … AC-010. None added, none dropped; the ledger matches.
2. **`discover.md`:33's deferred question — what "rendered" means before the URLs resolve — is pinned**, and it is pinned *differently per surface family*, which the discover stage left open. docs.rs is the **real renderer** (`cargo +nightly doc` under the same `RUSTDOCFLAGS` docs.rs uses); crates.io is a **local render of the packaged README** through `_design.md`'s dimensioned geometry; GitHub renders itself. The fidelity difference is not papered over — it is one of the three stated limits in the record.
3. **`discover.md`:34's deferred question — whether a post-publish re-read is warranted — is resolved as no**, with the reasoning recorded rather than left implicit: the project names no post-publish AC, only the renderer changes between the preflight and the live page, and both failure modes that change can introduce are already bounded (a dropped construct by AP-7 plus the constrained construct set; a failed docs build by the real `--cfg docsrs` build in this same read). The residual is written into the record.
4. **The crates.io read is on the packaged bytes, not the working tree.** The discover stage said "a faithful local render of each crate README" without settling *which* README. It is the one inside the `.crate`, because that is the only one crates.io can render.
5. **`.bklg/.../design/reference/` does not exist yet.** It is created by this story, which is why it appears in the PR boundary and in AC-008 but not in the anchors table — an anchor is something to open, and there is nothing there to open until this PR lands.
6. **Two `RUNBOOK.md` lines, not a phase-12 cleanup.** The stale four-crate goal (`:4450-4451`) and the stale `#the-46-provisional-clauses` anchor (`:4495`) are visible from the mount point and are deliberately left to `crate-set-decision`, `falsifier-ledger-repair` and `deferred-clause-reread`. The record says they were seen and left, so a later reader does not conclude they were missed.
7. **The pixel/line question is settled in favour of pixels.** `_design.md` states the budget in both rendered lines and pixels; the sign-off's own finding was that heading margins break the 24 px-per-line arithmetic. The record measures pixels at a stated zoom and uses lines only to explain.
8. **AP-6's link check is consumed, not re-implemented.** It is `landing-copy-and-status-truth`'s mechanical check (AC-UX-011); this story cites its result. Re-running it here would be a second implementation of a check that already has an owner.
9. **No conformance rule, no clause, no `spec/` path.** This project ships no adapter and touches no port; `event_store_conformance!` and `MemoryFixture` are cited only to record that the rule does not apply (`_decomposition.md`:509-512). Project AC-015 is satisfied here by the absence of a `spec/` path in the diff, which AC-009 asserts.

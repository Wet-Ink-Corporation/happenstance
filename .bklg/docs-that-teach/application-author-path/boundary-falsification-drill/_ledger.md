# Acceptance ledger — Removing the boundary makes the repository fail

The machine-checkable Definition-of-Done ledger for this story (RFC §6.5). One row per spec
`AC-###`. Planning authors every row with `satisfied: false`; the implementer may only flip a row to
`satisfied: true` and MUST cite real evidence (a `file:line` and/or the verifying test id) — never
edit, remove, or re-word a criterion, and never flip a satisfied row back. `redkiln verify --grain
story` reads the fenced block below and blocks `implement → report` unless every spec AC is present,
`satisfied: true`, and carries non-placeholder evidence (and no AC that was satisfied on the base
branch has regressed). Scope changes are a human decision recorded through `redkiln advance`, not a
quiet ledger edit.

Two mount points appear below and both are real. `xtask/src/narrative.rs` is HS-P0020's `HARNESS`
— the lib-crate registration file whose `include_str!` line makes the step-3 page a doctest the
`"tests"` REQUIRED step executes. `crates/happenstance/src/lib.rs` is the crate-root twin, executed
today by `cargo test -p happenstance --doc`, which is why AC-002…AC-004 have a proof that does not
wait on the pinned tree. Evidence for a page-side row must cite the page mount; evidence citing only
the twin leaves the page half unproven.

**The twin's mount moved during implementation, and the rows below name where it actually is.**
The merged crate root cannot carry a second fence — `crates/happenstance/tests/doc_budget.rs:157`
allows it exactly one and its module doc is at the 130-line ceiling — so the twin is
`crates/happenstance/tests/boundary_refusal.rs`, a `#[tokio::test]` executed by
`cargo test -p happenstance --test boundary_refusal` and swept by the same `"tests"` REQUIRED step.
The placement is pre-authorised by this story's own PR boundary (`crates/happenstance/tests/**`)
and the reasoning is `boundary-refusal-encounter/_conditions.md` § **BC-002**, restated in AC-002's
evidence. The `mount_point` fields say `crates/happenstance/tests/boundary_refusal.rs` rather than
the crate root because a machine-readable field that names a file carrying nothing for this story
is worse than no field at all.

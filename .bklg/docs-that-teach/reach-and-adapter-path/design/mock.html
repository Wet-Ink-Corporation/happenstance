Substrate — what is real here, and what is not

This stage exists to force the real primitives to be discovered before feature code is written. For this project the discovery is uncomfortable and it is stated first, because half the design rests on it.

Real, and inlined verbatim. target/doc/static.files/normalize-9960930a.css and target/doc/static.files/rustdoc-17e0aaed.css (69,637 bytes, rustdoc 1.97.1 (8bab26f4f 2026-07-14)) are embedded in this page byte-for-byte. The single edit is to @font-face src. The result makes zero requests of any kind — open it from file:// with the network off and it is identical.

The font trade, stated rather than hidden. Sixteen frames each parse this stylesheet, so an embedded face is paid sixteen times — embedding all eight of rustdoc's woff2 faces made the page heavy enough to paint nothing at all (measured, not feared). Two are inlined as data:font/woff2;base64: SourceCodePro-Regular-8badfe75.ttf.woff2, SourceSerif4-Regular-6b053e98.ttf.woff2 — the serif that sets the prose measure and the monospace that sets the fence width, which are precisely the two the density budget is written in. The rest (FiraMono-Medium-86f75c8c.woff2, FiraMono-Regular-87c26294.woff2, FiraSans-Italic-81dc35de.woff2, FiraSans-Medium-e1aa3f0a.woff2, FiraSans-MediumItalic-ccf7e434.woff2, FiraSans-Regular-0fe48ade.woff2, NanumBarunGothic-13b3dcba.ttf.woff2, SourceCodePro-It-fc8b9304.ttf.woff2, SourceCodePro-Semibold-aa29a496.ttf.woff2, SourceSerif4-Bold-6d4fd4c0.ttf.woff2, SourceSerif4-It-ca3b17ed.ttf.woff2, SourceSerif4-Semibold-457a13ac.ttf.woff2) keep their local() source only, so a machine with Fira Sans installed sees rustdoc's real headings and sidebar and one without sees the system sans. Headings and sidebar chrome may therefore differ slightly from docs.rs; the prose measure and the code column do not.

Every rustdoc frame below therefore carries rustdoc's own class contract, mirrored from this worktree's generated HTML rather than approximated: body.rustdoc.mod, nav.sidebar / .sidebar-crate / #rustdoc-toc / ul.block.top-toc, main > .width-limiter > section#main-content.content, .main-heading, details.toggle.top-doc > .docblock, h2/h3 > a.doc-anchor, .example-wrap > pre.language-text, dl.item-table. Sources: target/doc/happenstance/index.html and target/doc/happenstance/store/index.html.
Not real, and not faked into looking real. Three of the five surfaces have no renderer in this repository, and inventing one would be the exact failure this stage is here to catch.
  • readme-front-door is rendered by crates.io and by GitHub. Neither stylesheet exists in this tree, and neither is pinned by anything here. Its frames are therefore drawn two ways: a source pane with real line numbers — which is the artefact that actually exists, and the one _design.md's budget is written in — and a flat prose pane in this harness's own typography, labelled as such. Nothing in the prose pane may be read as an approved colour, weight or measure.
  • adapter-reasoning-account and evaluator-onward-links live in HS-P0020's pinned narrative tree, which does not exist. There is no book.toml, no mdBook, no site generator and no template anywhere in the repository (verified). _design.md deliberately omits their selector: for this reason. Their frames render composition and density only — heading ladder, reading order, where the caveat sits, where the single onward hop sits — in the same neutral harness typography, at the declared widths.
  • rustdoc's JavaScript (main-fcd733ba.js) is not loaded into the frames. The search box, the theme picker and the settings menu that main.js injects into <rustdoc-topbar> are consequently absent. That is a known and deliberate gap: it costs the topbar roughly its full height, so the fold markers below are, if anything, generous to the design.

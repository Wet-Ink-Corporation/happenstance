## One-line PR slice

Run `cargo xtask ci` — the terminal `e2e` grain — last, on the exact tree that already carries the atoms, the maps, `links.kb`, the reconciliation record, the DT audit and the fifteen-scenario ledger, and record it green.

## Executive summary

This PR lands **one observation and the record of it**: the whole gate, run once, from the slice's fresh checkout, on a named commit that already contains every artefact this project owes, plus the transcript and provenance that let a later reader re-run it and get the same answer.

The delta over what the project already has is small and entirely evidentiary. The gate itself exists and is wired (`.redkiln/config.yaml:60`, `xtask/src/main.rs:828-833`); this project "invents no new gate step" (`_decomposition.md:514-515`). What does not exist yet is a run that is *admissible* — one whose tree, ordering, invocation and skip-set are all recorded, so that "green" means the deliverable passed rather than that the gate did. Three things make an inadmissible run easy to produce by accident, and this spec exists to make each of them observable: running `--fast` (which silently drops four steps), running before the records are committed (which "proves the gate, not the deliverable" — `_decomposition.md:638-641`), and running on a tree that still carries scenario 2's deliberate break or the untracked residue of it.

It also settles the one genuine paradox in AC-016: the run record naming commit *S* cannot itself be in *S*. The resolution is stated as a checkable closure rule below, not left to the implementer to notice.

## Context pack

**The decision this story is downstream of, and may not re-open.** `.redkiln/config.yaml:60` wires `e2e: "cargo xtask ci"`, and `.bklg/docs-that-teach/_decomposition.md:306-308` makes `durable-audience-closeout` the only project created with `--terminal` — so this is the one project in the initiative held to the whole gate rather than to `integration_scoped` (`cargo xtask ci --fast`, `.redkiln/config.yaml:55`). The project brief names this as mount point 7 and immediately qualifies it: the gate "is a precondition for reading the DoD evidence, never a substitute for it" (`_decomposition.md:485-488`). This story therefore produces *evidence about a run*, not a verdict about the initiative.

**`--fast` is the named wrong implementation, and the difference is mechanical, not stylistic.** `run_ci` executes `REQUIRED` then `OPTIONAL` (`xtask/src/main.rs:828-833`); `run_fast` executes `REQUIRED` alone and says so in its own final line (`:853-860`). What `--fast` drops is exactly the release bar — the workspace feature powerset, the `wasm32` feature powerset, `cargo deny`, and the nightly `--cfg docsrs` rustdoc build (`:535-638`, four steps). Twenty `REQUIRED` steps (`:105-534`) plus those four is twenty-four `=== step ===` headers in a full transcript (`:864`); a `--fast` transcript carries twenty and a different closing line. The count is the cheapest falsifier this story has, and the spec uses it rather than trusting a reported command string.

**A skipped step is green and is not proof.** `run_steps` prints `skipped: \`<probe>\` did not succeed` and continues when a step's probe cannot find its tool (`xtask/src/main.rs:873-878`). CLAUDE.md is explicit that on this machine `cargo-hack` and `cargo-deny` both resolve, "so those steps run rather than printing `skipped`" and "a green local gate now proves more than it used to" (`CLAUDE.md:286-289`). The fresh checkout this slice runs in is a *different working directory on the same machine*, so the expectation transfers — but nightly may or may not be installed, and a skip there is a real, reportable narrowing rather than a failure. The record therefore transcribes the skip lines instead of summarising them away; a run in which `cargo deny` or either powerset printed `skipped` is a finding to state, not a green to claim.

**Ordering 4 is the whole point of the story's position.** The architecture brief fixes four non-negotiable orderings, and the fourth is *everything committed before the final gate run*: AC-016 requires the gate green "on **the exact tree carrying every artefact**", because "a gate run taken before the ledger and the reconciliation record are in the tree proves the gate, not the deliverable" (`_decomposition.md:627-641`). The testing brief restates it as an admissibility rule — merge-gate step 5 runs last, and an earlier run "does not count as AC-016's evidence" (`:830-832`, `:757-762`). This story is last in the project by construction (`_storymap.md:156-160`), and its first obligation is to *demonstrate* the ordering, not to assert it.

**The closure rule that makes ordering 4 satisfiable.** The gate is taken on commit `S`. The transcript, this story's `_ledger.md` and the provenance link cannot exist in `S` — they are produced by the run. They land in a follow-on commit `S+1` whose entire diff is confined to this story's own backlog folder (plus the slice-mate's evidence pointer, below). That is sound rather than a loophole because **no gate step reads anything under `.bklg/`**: a grep over `xtask/src` finds `.bklg/` mentioned in exactly one place, `affected.rs`'s inert-path list (`xtask/src/affected.rs:248-266`), where it is enumerated as reaching no package at all — and `affected` is the *story* grain, not a step of `ci`. So `git diff --name-only S HEAD` being confined to `.bklg/docs-that-teach/durable-audience-closeout/**` is a proof that re-running the gate at `HEAD` would take the same path through the same twenty-four steps. State the rule and show the diff; do not re-run the gate to chase your own tail.

**The checkout is a fixture, and it is not this worktree.** AC-A07 requires the re-observation to run "somewhere this planning did not" — a fresh `git clone` or `git worktree add` off the **merged** branch, never `.claude/worktrees/docs-that-teach` (`_decomposition.md:388-391`, `:789-794`). The slice's three stories run in the *same* fresh checkout (`_storymap.md:76-78`), so this story does not create one: it names the one `dod-scenario-ledger` created, records its path and sha, and — because the checkout was made before the last records were committed — must bring it to `S` (fetch/checkout) rather than assuming it is already there.

**Scenario 2's mutation must be provably absent at the moment of the run.** DoD-2 requires a page deliberately broken, the gate failing *by name*, then a revert to green (`initiative.md:416-420`); the architecture brief adds that the broken edit "is never a committed state of the tree the final `cargo xtask ci` (ordering 4) is taken on" (`_decomposition.md:642-647`), and AC-TB-05 makes its absence at merge-gate step 5 a criterion in its own right (`:837-839`). The falsifier is not a claim but a command: `git status --porcelain` empty at `S`, and the pinned page identical at `S` to its pre-break content. An uncommitted break is exactly what a dirty worktree hides.

**Validation order: `redkiln validate --kb` first, then the gate, both on the same tree.** AC-A08 (`_decomposition.md:392-395`) and AC-TB-07 (`:843-845`) both fix the order and both bind it to "the tree that already carries every artefact". The project's own Definition of Done repeats it and says why: the gate being green is a precondition for reading the evidence, never a substitute (`project.md:213-215`). This story runs both and records both shas; if the two differ, one of them is not evidence.

**What the gate proves about the rest of the diff, and what it does not.** This project ships no Rust — `crates/`, `spec/`, `xtask/`, `standards/` and `docs/` are read-only to it (`_decomposition.md:410-427`). AC-TB-08 says plainly that the gate's Rust-grain steps function here "as a regression net proving `crates/`, `examples/`, `spec/` and `standards/` stayed untouched … not as tests of new behaviour" (`:846-851`). Two steps inside the gate do carry sibling obligations forward: `specification traceability` (`xtask/src/main.rs:315-326`) re-runs `spec-trace` over the merged tree, which is DR-12's read — but the *written* completeness statement is `post-merge-clause-completeness`'s deliverable, not this one (`project.md:102-105`); and `packaged artifacts carry their licences and README` (`:519-534`). Neither is re-decided here.

**The persona-journey slice.** The reader is **U2, the closeout reviewer** — the second of this project's two audiences (`_decomposition.md:43-57`). U2 reads this record to answer one question: *was the thing that passed the same thing I am about to approve?* Every criterion below is a way of making that question answerable from the record alone, without re-running anything and without trusting the runner. The a11y floor applies verbatim: the verdict is a **word** (`green`), never a tick, a colour or an empty cell (AC-UX-09, `_decomposition.md:266-269`), and every row of the record is self-contained (AC-UX-10, `:270-273`) and names the tree it was taken against (AC-UX-12, `:278-281`).

**No Accepted decision atom reaches this surface, and citing one would be manufacturing authority.** All sixteen accepted decisions govern the Rust contract; the charter says so at `.bklg/docs-that-teach/initiative.md:524-525`, and the architecture brief repeats the finding rather than hunting for a documentation ADR (`_decomposition.md:494-503`). What binds instead is CLAUDE.md's single-writer rule for item frontmatter, `.redkiln/config.yaml`'s declared grains, and the two briefs above. Do not write an ADR as a side effect of a gate run (`project.md:124-127`).

## Implementation notes (non-prescriptive)

These are observations that save a wrong turn; none of them is a required design.

**A workable order.** Confirm the fixture exists and is at `S` (EC-007, EC-008) → `git status --porcelain` and the pinned-page diff (AC-004) → the artefact-presence check at `S` (AC-001) → `redkiln validate --kb` (AC-005) → `cargo xtask ci` with output captured to a file (AC-002, AC-003) → author the record in the initiative worktree (AC-006) → fill DoD-1's evidence pointer and this story's `_ledger.md`, commit, `redkiln record-links HS-S0182 --sha` → transcribe `git diff --name-only <S> HEAD` (AC-007). Everything before the gate is cheap; everything after it is authoring. Nothing after the gate re-runs it.

**Capturing without losing the console.** Any mechanism that writes the stream to a file while keeping it visible is fine (`tee`, PowerShell's `Tee-Object`, a redirect plus a follow). Do not paraphrase, re-order or re-indent the capture: the transcript is a capture and not a record format (see "Data and migrations"), and its only value is that nobody has to trust a summariser.

**Read `run_steps` before interpreting an odd transcript.** It prints the header, evaluates the probe, may print `skipped:` and `continue`, otherwise runs the step and bails on failure (`xtask/src/main.rs:862-892`). Every shape a transcript can take is in those thirty lines; a step that "did nothing" is either a skip line you missed or a step whose own output was quiet.

**The step count is a falsifier, not a decoration.** It is cheap to compute (`rg -c "^=== "`) and it is the only check in this story that a mistaken `--fast` cannot survive. Prefer it to reading back the command you believe you typed.

**Do not chase your own tail.** The temptation on seeing the closure rule is to commit the record and re-run the gate "to be safe". That produces a new sha needing a new record, forever. The closure argument — `.bklg/` reaches no gate step, and the `S`→`HEAD` diff is confined to it — is the evidence; show the diff instead.

**If the gate is green but a step skipped, the story is still reportable.** Record the skip as EC-003/EC-004 requires and say what is consequently unproven. A narrower-than-expected green, stated, is worth more to U2 than an unqualified one.

## Clarifications resolved during spec

1. **The seven AC-### ids are exactly those the first pass enumerated**, AC-001…AC-007, and none was added or dropped. They partition AC-016 into its clauses — exact tree, whole gate, complete skip set, clean tree, stated order, legible record, mounted result — rather than restating it seven times.
2. **AC-016's paradox is resolved by a closure rule, not by a second gate run.** The record naming `S` cannot be in `S`; it lands in `S+1`, whose diff is confined to `.bklg/` — a tree no `ci` step reads (`xtask/src/affected.rs:248-266`). Stated in the Context pack, carried by AC-007, and EC-009 is what happens when the diff escapes.
3. **"Green" is defined as the whole gate with its skip set declared**, not as a zero exit code. A `skipped:` line is green to the shell and is a narrowing to a reviewer; AC-003 and EC-003/EC-004 make the difference legible. This is a tightening of AC-016's plain words, taken from `CLAUDE.md:286-289` and `xtask/src/main.rs:873-878`, and it can only ever make the bar higher.
4. **The step count (24) is used as the falsifier for `--fast`** in preference to trusting a recorded command string. It is derived from `REQUIRED` (`xtask/src/main.rs:105-534`) plus `OPTIONAL` (`:535-638`) and independently confirmed by counting the `Step` declarations in that file. If a future change to `xtask` alters the count, AC-002's number moves with the code and the criterion's *mechanism* — count the headers, read the closing line — does not.
5. **This story creates no fresh checkout.** The slice runs in one (`_storymap.md:76-78`) created by `dod-scenario-ledger`; this story names it, brings it to `S` if it lags (EC-008), and treats its absence as a halting dependency failure (EC-007) rather than a thing to improvise.
6. **The "no rendered surface" sign-off does not vacate Interaction quality.** `_design.md:45-47` decides there is no screen; the UX brief decides what the markdown must look like, and says the colour-never-alone floor "binds *today*, in markdown" (`_decomposition.md:125-130`). Every applicable invariant is therefore carried by an AC row in the table, not by a bullet in that section.
7. **No ADR is cited and none is written.** All sixteen accepted decision atoms govern the Rust contract (`initiative.md:524-525`; `_decomposition.md:285-296`); citing one here would manufacture authority, and writing one as a closeout by-product is explicitly out of scope (`project.md:124-127`).
8. **A gate failure originating in read-only directories is routed, not fixed** (EC-002). This was implicit in the project's non-goal about incidental bugs (`project.md:128-129`); it is made an explicit error condition because the terminal gate is the most likely place in the whole initiative for such a bug to surface.
9. **The record's file name is the implementer's choice** — `_gate-run.md` is a working name, as `_dod-reobservation.md` is for the slice-mate (`dod-scenario-ledger/spec.md:166-173`). The *directory* and the citation obligations are not negotiable; the ledger's `verifying_test` fields name the working path and must be updated to whatever name lands, in the same commit.

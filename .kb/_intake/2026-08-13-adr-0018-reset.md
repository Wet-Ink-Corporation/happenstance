## Claims the atom carries — four halves, three strengths, not levelled

The point of this atom is that the four are **not** of equal strength, and an
atom that presents them as one flat list has lost the decision's shape.

1. **`reset(batch, id)` applies the batch and returns `id`'s checkpoint to
   `NeverRun` as one unit of work (PS-16, `[PROVISIONAL]`).** The caller fills the
   batch with its own deletes, because *"the port has no idea what the read model
   is"* (`spec/SPECIFICATION.md:5165-5170`); `ProjectionProbe::probe_delete_all`
   (ADR-0017) exists so the suite can exercise it without knowing either. The atom
   carries the **failure it models** rather than asserting atomicity abstractly:
   the two-statement runbook procedure on two connections, where *"the truncate
   committed at 02:46:31, the pod died at 02:46:33 … applied sixty-one events into
   an empty table and **reported healthy**"* (`:5181-5187`).
   *Falsifier:* an adapter whose read-model clearing cannot be expressed through
   the same batch that carries ordinary writes; a store whose `TRUNCATE` cannot
   participate in the checkpoint transaction is the shape to watch.
   *Phase:* the projection-port phase.
2. **Scope is one `(store, ProjectionId)` pair (PS-17, `[FROZEN]`) — settled by a
   prior decision, cited and not re-derived.** ADR-0007 already fixed checkpoints
   there; PS-17 is *"the same decision applied to the operation that removes one"*
   (`:5190-5191`). The atom **cites** `kb-decision-0007` and stops. A second
   independent derivation of one commitment is two things to keep in agreement.
3. **Refusal is a port *mechanism*, with the policy in the domain (PS-18,
   `[PROVISIONAL]`).** `ResetError::Refused`; a refusal leaves both halves
   unchanged and is not reported as success. The alternative that lost is
   **refusal as purely a typed-layer concern** — that is where the *policy*
   belongs, but *"a policy with no port-level mechanism is bypassed by anyone
   holding the store, which is every operator with a runbook"* (`:5211-5215`).
   *Falsifier:* no adapter ever implements protection, in which case the variant is
   dead weight. *Phase:* evaluated at the projection-port phase exit by asking
   whether the SQLite adapter implemented it.
4. **`Checkpoint` is a three-variant enum — `NeverRun` / `Live { through }` /
   `Rebuilding { through }` — settled by being made.** `(Option<SequencePosition>,
   bool)` loses because it can spell `(None, true)`: *"authoritative, never run —
   which means nothing"* (`:4643-4658`). PS-19 and PS-20 both rest on it.

**What the atom does not decide:** whether `ResetError::Refused` carries the
store's stated reason or stays bare. That is a public-API shape question and it
belongs to the design record (`projection-api-design-record`, project AC-007),
where it is decided out loud rather than defaulted to silence.

## Rejected alternatives the atom must name, each with its reason

- the two-statement runbook procedure — the incident above; not a straw man, it is
  what was actually run;
- `reset` clearing the rows itself — requires the adapter to know which tables,
  labels or keys belong to a `ProjectionId`, which is exactly the knowledge PS-9
  keeps out of the port;
- refusal as purely a typed-layer concern — the policy belongs there, the mechanism
  cannot;
- `(Option<SequencePosition>, bool)` for the checkpoint, and its weaker form, a
  bare `Option<SequencePosition>`, which cannot distinguish a rebuild in flight
  from an authoritative read model at all;
- re-deriving PS-17's scope from first principles.

## The evidence to quote: a stated absence

No skeleton exercised `reset` — every skeleton body is `todo!()`. The atom quotes
the **absence**, from `references/adapter-shapes.md:286-303`:
*"Durability | **Nothing. Every body is `todo!()`** | Phase 8"*, and
*"Batch shape | … | The projection conformance suite, which does not exist. Phase
6"*. A fabricated diagnostic would be a defect, not a stronger record —
`:29-33` argues this in the document's own voice.

## PS-19's pairing defect: named, scoped out, attributed — and not repaired

PS-19's `MUST` is scoped *after a successful reset*; §4.11 additionally assigns it
`fresh_projection_has_no_checkpoint`, which asks about an id never seen. The
exposing store is natural: `checkpoint` is
`SELECT position, authority FROM checkpoints WHERE id = ?` resolving a missing row
with `.unwrap_or(Checkpoint::Live { through: FIRST })`, and `reset` writes an
explicit `NeverRun` sentinel. Widening the clause changes the set of
implementations it admits, so it is a **gap** and a gap is a decision's — landing
at `unstable-projection-gate-and-clause-disposition` under
`kb-playbook-repair-frozen-clause-001`. **The atom states this and repairs
nothing.**

The sweep's family verdict is **isolated**, so this atom's scope is not widened.
One wording ambiguity in range is recorded and routed rather than fixed: PS-18's
rule is described as running *"against a testkit fixture store configured to
protect one id"*, which in an adapter suite must mean the adapter's own fixture —
`reset-rules` and `projection-capability-skips` close it.
